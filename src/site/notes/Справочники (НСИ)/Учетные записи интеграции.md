Справочник **`УчетныеЗаписиИнтеграции`** задаёт клиентские ключи и ограничения доступа к HTTP-сервису **StockAPI**. Каждая запись — отдельный внешний интегратор (или служебный ключ-администратор).

Авторизация запросов: заголовок `X-Api-Key` = реквизит `ТокенАвторизации`. Неактивная, помеченная на удаление или неизвестная запись → **401**.

Созданные через API [[Документы/📄Инвойс продажи\|заказы]] (`ИнвойсПродажи`) сохраняют ссылку на учётную запись в реквизите `УчетнаяЗапись`.

## Реквизиты шапки

| Реквизит | Тип | Назначение |
| --- | --- | --- |
| `Код` | Число | Автонумерация |
| `Наименование` | Строка (40) | Представление записи |
| `Активен` | Булево | Участие в авторизации API. При пометке на удаление сбрасывается в `Ложь` |
| `Администратор` | Булево | Расширенный доступ (см. ниже) |
| `ТокенАвторизации` | Строка | Секрет для `X-Api-Key`. На форме — команда генерации (SHA-256) |
| `Комментарий` | Строка | Произвольное описание |
| `РазрешитьПревышениеЦен` | Булево | В POST/PATCH/PUT `/orders` разрешены цены **выше** регистра `ЦеныПродажи` |
| `РазрешитьСнижениеЦенНа` | Число (3.1, ≥ 0) | Допустимое снижение цены относительно регистра, **%**. `0` / пусто — снижение запрещено |
| `WebhookАктивен` | Булево | Включить исходящие webhook. Без заполненного `WebhookURL` флаг не включается |
| `WebhookURL` | Строка | URL приёмника уведомлений |
| `WebhookToken` | Строка | Токен, передаваемый при отправке webhook |
| `ОтправлятьОстатки` | Булево | Участвовать в событиях изменения остатков |
| `ОтправлятьЦены` | Булево | Участвовать в событиях изменения цен (`УстановкаЦен`) |

### Цены в заказах

При создании/изменении заказа `price` строк сверяется с `ЦеныПродажи` (вид цены + склад + валюта, с порогами количества):

| Настройка | Поведение |
| --- | --- |
| оба реквизита выключены / пусты | только точное совпадение с регистром |
| `РазрешитьПревышениеЦен = Истина` | цена запроса может быть **выше** регистра |
| `РазрешитьСнижениеЦенНа > 0` | цена запроса может быть **ниже**, но не меньше `регистр × (1 − %/100)` |
| выход за допуск | ошибка API с текстом допустимого диапазона |

### Администратор

При `Администратор = Истина`:

- не применяются ограничения по ТЧ **Склады** и **Контрагенты**;
- поиск заказов по номеру — среди всех заказов API (не только своей учётной записи);
- **GET /orders** без фильтра по покупателю — заказы всех контрагентов с заполненной `УчетнаяЗапись`;
- **GET /counterparties/groups** — группы из ТЧ «Контрагенты» **всех активных** учётных записей.

Для обычной записи доступны только свои склады, группы контрагентов и свои заказы.

## Табличные части

### Склады

| Реквизит | Описание |
| --- | --- |
| `Склад` | Ссылка на `Склады`, разрешённый этой учётной записи |

Используется в GET `/warehouses`, выборе склада в заказах/остатках/ценах, поиске сотрудников-операторов. Администратор — без отбора по ТЧ.

### Контрагенты

| Реквизит | Описание |
| --- | --- |
| `ГруппаКонтрагентов` | Папка справочника `Контрагенты` |

Обычная запись работает только с [[Справочники (НСИ)/Контрагенты\|контрагентами]] из указанных групп (поиск, создание, список заказов). Создание контрагента через API — в одну из групп этой ТЧ (`groupCode`).

### Идентификация сотрудников

Настраивает, для каких **изменяющих** методов StockAPI (не GET) обязателен `employeeCode` / `employeePin`.

| Реквизит | Описание |
| --- | --- |
| `ИмяМетода` | Имя обработчика HTTP-сервиса StockAPI (из списка mutating-методов) |
| `ОбязательныйСотрудник` | Если `Истина` — без сотрудника метод вернёт ошибку |

На форме: список выбора из метаданных StockAPI, команда **«Заполнить методы»** добавляет недостающие имена. При записи проверяются уникальность имени и принадлежность к mutating-обработчикам.

Сотрудник должен быть оператором склада из разрешённых учётной записи (`GET /employees`).

## Webhook

Условия отправки из очереди:

1. учётная запись **активна**;
2. `WebhookАктивен = Истина`;
3. заполнен `WebhookURL`;
4. для события остатков — `ОтправлятьОстатки`; для цен — `ОтправлятьЦены`.
