Справочник покупателей, поставщиков и прочих партнёров. Иерархический: **группы** (папки) и **элементы** (сами контрагенты).

### Группы (папки)

Группы упорядочивают контрагентов (поставщики / покупатели / офисы / регионы и т.п.) и задают общую аналитику для ветки.

| Поле группы | Назначение |
|---|---|
| **Код, наименование** | Идентификация папки |
| **Родитель** | Вложенность групп |
| **Офис** | Единственный реквизит «только для группы»: привязка всей ветки к офису |

Особенности групп:
- **Офис** заполняется на группе, не на элементе. В платёжном календаре отбор идёт по `Контрагент.Родитель.Офис` — офис смотрите у **родительской группы**.
- Ограничение доступа пользователю задаётся **группами**: в карточке пользователя в ТЧ «Контрагенты» указываются группы; доступ — «разрешить» или «запретить» по иерархии (видны/скрыты все контрагенты внутри этих папок).
- Именование вроде «Поставщик…» используется в контроле ввода (проверка псевдонимов у поставщиков).

Практика: сначала дерево групп с офисами, затем элементы внутрь нужных папок.

#### Псевдоним (отображение)
- Если у пользователя нет права видеть наименования — в списках и выборе показывается **псевдоним** (если заполнен).
- Иконка «зашифрован» — вместо имени будет псевдоним.
- Для поставщиков псевдоним обычно обязателен по регламенту контроля данных.

### Комиссионер

Пометка **Комиссионер** — булев реквизит элемента (на группе не используется). Сама по себе она не делает документы комиссионными: передача и заказ по-прежнему задаются признаками документов (`Комиссия` у расходной накладной, вид заказа «Заказ комиссионера» у [[Документы/📄Инвойс продажи\|📄Инвойс продажи]]). Пометка нужна, чтобы контрагента можно было провести как комиссионера и чтобы в карточке появились связанные поля.

В карточке при включении пометки показываются **% комиссионного вознаграждения** и **Склад комиссии** (отбор выбора: только склады с `СкладКомиссии`). При снятии пометки поля скрываются, значения в базе не очищаются.

Где пометка **проверяется**:

| Место | Что происходит |
|---|---|
| **Расходная накладная** с `Комиссия` | При проведении: у контрагента должен быть **Комиссионер**, иначе «У контрагента должен быть признак комиссионера.» Отдельно: склад комиссии документа должен быть заполнен и сам иметь признак склада комиссии; в ТЧ только товар. |
| **Отчёт комиссионера**, возврат от покупателя | При проведении: тот же обязательный признак у контрагента («У контрагента должен быть установлен признак «Комиссионер».»). |
| **Отчёт комиссионера**, продажа | Признак **Комиссионер** не проверяется. Берётся **% комиссионного вознаграждения** контрагента: доход в `РасходыДоходы` умножается на `(1 − % / 100)`. |
| **Привязка долгов** (оплата покупателя в [[Документы/📄Движение денег (кассовый ордер)\|📄Движение денег (кассовый ордер)]]) | Состав документов тот же (остатки регистра `Долги`). Меняется заголовок формы: «оплата (привязка) долгов **комиссионера**» вместо «долгов покупателя». |

Связанное поле **Склад комиссии** контрагента (не путать со складом документа и с признаком склада):

- в расходной накладной при включении `Комиссия`, если склад комиссии документа пуст, подставляется `Контрагент.СкладКомиссии`;
- при создании расходной по заказу комиссионера через API (`POST /delivery`) склад комиссии документа берётся с контрагента заказа; если пуст — ошибка «По заказу комиссионера укажите склад комиссии у контрагента.»;
- то же при импорте отчёта торговой площадки (расходная с `Комиссия`).

Заказ комиссионера (`ИнвойсПродажи`, вид «Заказ комиссионера») **не** проверяет пометку **Комиссионер**: вид заказа задаётся в документе / API (`consignment`). Без пометки такой заказ создать можно, но расходную с `Комиссия` по нему провести нельзя.

Схема учёта комиссии (передача РН, отчёт, возврат, переоценка) — в [[Документы/Комиссионная торговля/Комиссия\|Комиссия]].

### Доступ
В **Пользователе**:
1. ТЧ **Контрагенты** — список **групп**.  
2. **Вариант доступа** — разрешить только эти группы (с подчинёнными) или запретить их.

Пустая ТЧ — без ограничения по контрагентам. Отбор действует в списках документов (накладные, инвойсы и т.д.).

---

### Практика
1. Создайте группы (Поставщики, Покупатели…) и укажите **Офис**.  
2. Заведите элементы в нужных группах.  
3. Для поставщиков заполните **псевдоним**.  
4. При необходимости включите **Привязывать инвойсы**.  
5. Для комиссионера включите **Комиссионер**, укажите **склад комиссии** и **% вознаграждения**.  
6. Ограничьте доступ пользователям через группы в их карточке.
