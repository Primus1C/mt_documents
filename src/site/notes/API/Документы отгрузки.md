# GET `/api/v1/delivery-notes`

**Описание:** получение расходной накладной в формате PDF или Excel

**Запрос**

    GET /trade/hs/stock/delivery-notes

**Параметры**

| параметр                                       | допустимые значения                 | описание                                                                                              | обязательный |
| ---------------------------------------------- | ----------------------------------- | ----------------------------------------------------------------------------------------------------- | ------------ |
| number \| deliveryNumber \| deliveryNoteNumber |                                     | номер расходной накладной в 1С                                                                        | +            |
| date \| deliveryDate                           |                                     | дата расходной накладной                                                                              | -            |
| format                                         | pdf \| excel \| xlsx \| xls \| json | формат накладной (по умолчанию **pdf**)                                                               | -            |
| serials                                        | with \| without                     | вариант накладной: с разделением по сериям, либо сводно по товарам без серий  (по умолчанию **with**) | -            |
**Пример запроса**
GET /delivery-notes?number=РН-000123&format=pdf&serials=without

**Успешный ответ**
Бинарный PDF-файл, или JSON. В JSON (`format=json`) поле `items[].price` — цена строки расходной накладной: при отгрузке через `POST /delivery` с `items` у одного `itemCode` могут быть разные `price` (как в строках заказа).


# POST `/api/v1/delivery`

**Описание:** Метод создаёт одну [[Документы/📄Расходная накладная\|Расходную накладную]] по заказу ([[Документы/📄Инвойс продажи\|📄Инвойс продажи]]) на основании переданных серийных номеров (IMEI). Отгрузка всегда полная — по всем позициям заказа.

Тело запроса — **один** из двух форматов (оба сразу передавать нельзя):

- `serials` — только серии. Цена в расходной берётся из заказа **по номенклатуре** (если товар в заказе несколькими строками с разными ценами, всем единицам этого товара ставится цена **последней** строки).
- `items` — серия + товар + цена. Цена каждой единицы берётся из той строки заказа, у которой совпадают номенклатура и `price` (как в `GET /orders` → `items.price`). Так в `GET /delivery-notes` у одинакового товара могут быть разные цены.

**Запрос**

    POST /trade/hs/stock/delivery

**Параметры**

| параметр | описание | обязательный |
| --- | --- | --- |
| orderNo \| number \| orderNumber \| incomingNumber | номер заказа: входящий (`НомерВходящий`) или номер документа в 1С | + |
| serials | массив серийных номеров товаров (старый формат) | + (если нет `items`) |
| items | массив позиций: `itemCode` (или `item`), `price`, `serial` | + (если нет `serials`) |
| employeeCode | код сотрудника в 1С | - |
| employeePin | пин сотрудника (используется, если не задан код сотрудника) | - |

**Пример запроса (`serials`)**

```json
{
    "orderNo": "API-0122",
    "employeePin": "1234",
    "serials": [
        "5423467471235446",
        "45678567867457",
        "23452345674575678"
    ]
}
```

**Пример запроса (`items`) — разные цены одного товара**

```json
{
    "incomingNumber": "PO-2026-001",
    "employeePin": "1234",
    "items": [
        { "itemCode": "19452", "price": 100, "serial": "353794238870860" },
        { "itemCode": "19452", "price": 110, "serial": "356701755737320" }
    ]
}
```

**Ответ 200**

```json
{
 "success": true,
 "error": "",
 "number": "МТ-0356879"
}
```

## Проверки (в порядке выполнения)
### 1. Авторизация (до вызова функции)

- Проверяется API-ключ запроса.
- Определяется учётная запись интеграции, от имени которой выполняется операция.
### 2. Формат запроса

| Проверка | Сообщение об ошибке |
| --- | --- |
| Указан номер заказа | «Не указан номер заказа входящий (incomingNo или incomingNumber или incoming), или номер 1С (orderNo или orderNumber или order).» |
| Есть `serials` **или** `items` | «Укажите массив serials или массив items.» |
| Не переданы оба массива сразу | «Укажите serials или items, но не оба.» |

**Формат `serials`**

| Проверка | Сообщение об ошибке |
| --- | --- |
| В теле есть массив `serials` | «В теле запроса нет массива serials.» |
| `serials` — массив | «Поле serials должно быть массивом.» |
| После разбора массив не пуст | «Массив serials пуст.» |

Разбор `serials`:
- пустые значения пропускаются;
- дубликаты отбрасываются (сравнение без учёта регистра);
- числовые серии приводятся к строке.

**Формат `items`**

| Проверка | Сообщение об ошибке |
| --- | --- |
| `items` — массив | «Поле items должно быть массивом.» |
| После разбора массив не пуст | «Массив items пуст.» |
| Элемент — объект | «Строка N: неверный формат позиции.» |
| Указан `serial` (синоним `serialNumber`) | «Строка N: укажите serial.» |
| Серия не повторяется в запросе | «Строка N: серия … повторяется в запросе.» |
| Указан `itemCode` или `item` | «Строка N: укажите itemCode или item (наименование).» |
| Указан `price` > 0 (синоним `salePrice`) | «Строка N: укажите price (цена строки заказа).» |

### 3. Поиск заказа

Заказ ищется по входящему номеру (`НомерВходящий`) или по номеру документа в 1С (`Номер`) — см. поля `incomingNumber` / `orderNumber` (синонимы `orderNo`, `number`, `incoming`).

|Проверка|Сообщение об ошибке|
|---|---|
|Заказ найден|«Заказ … не найден.»|
|Заказ принадлежит той же учётной записи API|«Заказ … принадлежит другой учетной записи API-клиента.»|
|Заказ не помечен на удаление|«Заказ … удален.»|
### 4. Состояние заказа

| Проверка                                                   | Сообщение об ошибке                                                            |
| ---------------------------------------------------------- | ------------------------------------------------------------------------------ |
| Заказ проведён                                             | «Заказ … не проведён.»                                                         |
| Тип документа — не финальный «Инвойс» (заказ покупателя или заказ комиссионера) | «Расходную накладную можно создавать только на основании проформы или заказа.» |
| По заказу ещё нет расходной накладной                      | «По заказу уже создана: … (проведена / не проведена).»                         |
> На один заказ допускается только одна расходная накладная.

### 5. Состав заказа

|Проверка|Сообщение об ошибке|
|---|---|
|В заказе есть товары|«В заказе нет товаров.»|
|Все позиции ведут серийный учёт|«Позиция «…» не ведёт серийный учёт.»|
### 6. Соответствие серий заказу

Для каждой серии из `serials`:

| Проверка | Сообщение об ошибке |
| --- | --- |
| Серия найдена в справочнике Партии (не помечена на удаление) | «Серия … не найдена.» |
| Товар серии входит в состав заказа | «Серия …: товар не входит в состав заказа.» |

Для каждой позиции `items` дополнительно:

| Проверка | Сообщение об ошибке |
| --- | --- |
| Серия найдена в справочнике Партии | «Строка N: серия … не найдена.» |
| Серия принадлежит указанному `itemCode` / `item` | «Строка N: серия … принадлежит товару «…», а не «…».» |
| Товар серии входит в состав заказа | «Строка N: серия … — товар не входит в состав заказа.» |
| `price` совпадает со строкой заказа по этому товару, и по этой цене ещё есть неиспользованное количество | «Строка N: цена … не соответствует строкам заказа для товара «…» (или количество по этой цене уже исчерпано).» |
| Все строки заказа с данной ценой закрыты сериями | «По товару «…» не отгружены все строки заказа с ценой … (осталось N).» |

После разбора всех серий (оба формата):

| Проверка | Сообщение об ошибке |
| --- | --- |
| Общее число серий = общему количеству товаров в заказе | «Количество серий (N) не совпадает с количеством товаров в заказе (M).» |
| По каждой номенклатуре число серий = количеству в заказе | «По товару «…» передано серий N, в заказе M.» |

> [!warning] 
> Частичная отгрузка не поддерживается — нужно передать серии ровно на весь заказ. 

 > [!attention] 
> В формате `serials` цена в расходной **не** выбирается по серии: у номенклатуры одна цена (последняя строка заказа; для заказа комиссионера — последняя `ЦенаКомитента`). Разные цены одного товара в `GET /delivery-notes` возможны только при отгрузке через `items`. 

### 7. Подбор партий и остатки на складе

При заполнении строк расходной накладной для каждой серии:

|Проверка|Сообщение об ошибке|
|---|---|
|На складе заказа и фирме заказа найдена ровно одна партия с остатком ≥ 1|«Не найдена партия на складе для серии ….»|
|Не найдено несколько партий одновременно|«Для серии … найдено несколько партий на складе.»|

Это единственная проверка фактического наличия товара: серия должна быть на складе заказа с ненулевым остатком.

### 8. Проведение документа

- Расходная накладная создаётся на основании заказа (контрагент, склад, валюта).
- Для **заказа комиссионера** (`Проформа = ЗаказКомиссионера`): у учётной записи API должен быть заполнен `СкладКомиссии` (иначе «По заказу комиссионера укажите склад комиссии в учётной записи API.»); документ проводится с `Комиссия = true`, `СкладКомиссии` из учётной записи.
- Цена строки расходной (`ЦенаПродажи`):
  - `serials` — по номенклатуре: цена продажи последней строки заказа, для заказа комиссионера — последняя `ЦенаКомитента`;
  - `items` — `price` из запроса, сопоставленный со строкой заказа (`Товары.Цена`).
- Документ записывается с проведением.
- При ошибке проведения: «Не удалось провести расходную накладную: …»

---

## Что не проверяется отдельно

- Свободные остатки по номенклатуре (как при создании заказа через `/orders`) — на этапе валидации не считаются; проверяется только наличие конкретной серии на складе.
- Статус заказа в регистре состояний (например, «готов к отгрузке») — не проверяется.
- Повторная отгрузка части заказа — не поддерживается по дизайну.


# PATCH `/api/v1/delivery`

**Описание:** метод переводит заказ в статус **«Собирается (заблокирован)»**. Требуется уже существующая расходная накладная по заказу (созданная в 1С или через **POST /delivery**). Серии в этом методе **не** передаются.

**Запрос**

    PATCH /trade/hs/stock/delivery

```json
{
    "orderNumber": "MT-20260708-00042",
    "incomingNumber": "PO-2026-001",
    "employeePin": "1234"
}
```

**Параметры**

| параметр | описание | обязательный |
| --- | --- | --- |
| orderNumber \| orderNo \| order \| incomingNumber \| incomingNo \| incoming | номер заказа (достаточно одного) | + |
| employeeCode | код сотрудника в 1С | - |
| employeePin | PIN сотрудника (если не задан код) | - |

`orderNumber` / `incomingNumber` / `employeeCode` / `employeePin` допускаются в теле JSON или в query string.

**Успешный ответ**
```json
{
  "success": true,
  "orderNumber": "00001234",
  "incomingNumber": "ORD-1001",
  "deliveryNumber": "00000567",
  "status": "Собирается (заблокирован)",
  "statusDate": "2026-07-13T16:30:00"
}
```

Нет накладной по заказу → **404**. Заказ уже заблокирован или отгружен → **409**.
