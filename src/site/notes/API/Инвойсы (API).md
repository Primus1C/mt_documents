# StockAPI — Инвойс закупки (`/invoices`)

HTTP-сервис **StockAPI**: создание, замена, добавление и удаление позиций, чтение [[Документы/📄Инвойс\|инвойсов закупки]].

---

## Авторизация

```
X-Api-Key: <токен учётной записи интеграции>
```

Неактивная или неизвестная [[Справочники (НСИ)/Учетные записи интеграции\|учётная запись]] → **401**.

Ограничения учётной записи:
- **поставщики** — иерархии групп из ТЧ «Поставщики» (см. `GET /sellers`).

[[Справочники (НСИ)/Склады\|Склады]] **не** используются.

### Формат запросов и ответов

| Метод | Тело запроса                                                                                      | Ответ       |
| ----- | ------------------------------------------------------------------------------------------------- | ----------- |
| GET    | —                                                                                                 | JSON, UTF-8 |
| POST   | `application/json` **или** `multipart/form-data` (см. [[API/Инвойсы (API)#Прикреплённые файлы\|#Прикреплённые файлы]]) | JSON        |
| PUT    | `application/json` **или** `multipart/form-data` (см. [[API/Инвойсы (API)#Прикреплённые файлы\|#Прикреплённые файлы]]) | JSON        |
| DELETE | `application/json`                                                                                | JSON        |

Даты в параметрах и теле: `yyyy-MM-dd`. В ответе: `yyyy-MM-ddTHH:mm:ss`.

### Сотрудник (опционально)

Два разных поля, не подменяют друг друга:

| Поле | Куда идёт | Методы |
|------|-----------|--------|
| `employeeCode` / `employeePin` | Идентификация оператора склада в изменяющем запросе (настройка «обязательный сотрудник» учётной записи). В реквизит `Менеджер` **не** пишется | POST, PUT, DELETE |
| `managerCode` | Реквизит шапки `Менеджер` (справочник `Сотрудники`) | GET (ответ и фильтр списка), POST, PUT |

Если в учётной записи включена обязательная идентификация — в теле или query POST/PUT/DELETE нужен `employeeCode` или `employeePin`. Если выключена — поля можно не передавать.

Коды менеджеров: `GET /employees?position=manager`. Коды операторов: `GET /employees?position=operator&warehouseCode=...`.

## Эндпоинты

| Метод | URL | Назначение |
|-------|-----|------------|
| GET | `/invoices` | Один инвойс или список с пагинацией |
| POST | `/invoices` | Создание или полная замена (upsert); опционально — массив вложений `attachment[]` |
| PUT | `/invoices` | Добавление позиций в существующий инвойс; опционально — массив вложений `attachment[]` |
| DELETE | `/invoices` | Удаление позиций; если в документе не остаётся строк — пометка инвойса на удаление |

## Пагинация (GET `/invoices`)

| Параметр | Синоним | Описание |
|----------|---------|----------|
| `page` | — | Номер страницы, с 1 (по умолчанию 1) |
| `pageSize` | `limit` | Размер страницы, 1–500 (по умолчанию 500) |

Ответ всегда содержит: `page`, `pageSize`, `totalItems`, `totalPages`, `items[]`.

## GET `/invoices`

**Назначение:** получить один [[Документы/📄Инвойс\|📄Инвойс]] или список инвойсов поставщиков, доступных учётной записи.

**Запрос:**  
`GET /trade/hs/stock/invoices?...`

Ответ **всегда** в виде списка с пагинацией. Даже для одного документа в `items` будет один элемент.

### Режим одного инвойса

Указан номер документа 1С и/или номер инвойса поставщика:

```
GET /invoices?number=000001234
GET /invoices?supplierNumber=INV-7788
GET /invoices?number=000001234&date=2026-08-25
GET /invoices?supplierNumber=INV-7788&sellerCode=1201
```

| Параметр         | Синонимы                     | Описание                                                           |
| ---------------- | ---------------------------- | ------------------------------------------------------------------ |
| `number`         | `invoiceNumber`, `invoiceNo` | Номер документа `Инвойс` в 1С                                      |
| `supplierNumber` | `supplierNo`                 | Номер инвойса поставщика (`ВКД_НомерИнвойсаПоставщика`)            |
| `date`           | `invoiceDate`                | Дата документа (`yyyy-MM-dd`) — уточнение при неоднозначном номере |
| `sellerCode`     | `supplierCode`, `code`       | Код поставщика (опционально)                                       |
| `alias`          | `seller`, `supplier`         | Псевдоним поставщика (опционально)                                 |

Достаточно одного из номеров (можно оба). Документ должен относиться к поставщику из ТЧ «Поставщики» [[Справочники (НСИ)/Учетные записи интеграции\|учётной записи]]. Помеченные на удаление не возвращаются → **404**.

Если найдено несколько документов — **400** (уточните `date` и/или `sellerCode` / оба номера).

### Режим списка

Номер не указан. Фильтр по поставщику и/или периоду даты документа:

```
GET /invoices?sellerCode=1201&dateFrom=2026-08-01&dateTo=2026-08-31&page=1&pageSize=50
GET /invoices?dateFrom=2026-08-01&dateTo=2026-08-31
GET /invoices?managerCode=5
GET /invoices?eta=2026-09-01
```

| Параметр | Синонимы | Описание |
|----------|----------|----------|
| `sellerCode` | `supplierCode`, `code` | Код поставщика |
| `alias` | `seller`, `supplier` | Псевдоним / наименование поставщика (как в POST) |
| `dateFrom` | `from` | Начало периода по дате документа (`yyyy-MM-dd`) |
| `dateTo` | `to` | Конец периода по дате документа (`yyyy-MM-dd`) |
| `managerCode` | — | Код сотрудника (`Сотрудники.Код`) — менеджер шапки инвойса |
| `eta` | — | Дата на складе отправителя (`ДатаНаСкладеОтправителя`), `yyyy-MM-dd` |

Без `sellerCode`/`alias` — все инвойсы поставщиков из иерархии групп ТЧ «Поставщики» учётной записи. `managerCode` и `eta` необязательны и сочетаются с остальными фильтрами. Период `dateFrom`/`dateTo` задаётся **парой**; при указании только одной границы или неверном формате — **400**. `dateFrom` не может быть позже `dateTo`. Некорректный (нечисловой) `managerCode` или неверная дата `eta` — **400**.

### Успешный ответ (200)

```json

  "page": 1,
  "pageSize": 50,
  "totalItems": 1,
  "totalPages": 1,
  "items": [
    {
      "number": "000001234",

      "seller": "Supplier Ltd",
      "sellerCode": "1201",
      "manager": "Иванов И.И.",
      "managerCode": "5",
      "currency": "USD",
      "supplierNumber": "INV-7788",
      "supplierDate": "2026-08-25T00:00:00",
      "posted": true,
      "amount": 761,
      "discount": 10,
      "local": false,
      "inspectionDate": "2026-08-20T00:00:00",
      "localStatus": "In transit",
      "deliveryFee": 25.5,
      "note": "API invoice",
      "eta": "2026-09-01T00:00:00",
      "items": [
        {
          "item": "iPhone 15",
```

Структура элемента списка совпадает с полями успешного **POST** (без `success` / `error` / `replaced`): `number`, `date`, `seller`, `sellerCode`, `manager`, `managerCode`, `currency`, `supplierNumber`, `supplierDate`, `posted`, `amount`, `discount`, `local`, `inspectionDate`, `localStatus`, `deliveryFee`, `note`, `eta`, `items[]`. Незаполненный менеджер / ETA — пустые строки `manager` / `managerCode` / `eta`.

Прикреплённые в 1С к [[Документы/📄Инвойс\|инвойсу]] файлы в ответ **не** входят: нет массива `attachment`, полей `fileName` / `fileContent` и отдельного эндпоинта скачивания. Файлы видны в интерфейсе 1С на форме документа `Инвойс`.

### Ошибки GET

| HTTP | Когда |
|------|--------|
| **401** | Нет / неверный `X-Api-Key` |
| **400** | Некорректные параметры (в т.ч. `managerCode`, `eta`); несколько документов на один номер; поставщик не найден |
| **404** | Инвойс не найден (в т.ч. вне поставщиков учётной записи) |
| **500** | Непредвиденная ошибка сервера |

```json
{
  "error": "Текст ошибки"
}
```

## POST `/invoices`

**Назначение:** создать инвойс или полностью заменить существующий (upsert) и провести документ.

**Запрос:**  
`POST /trade/hs/stock/invoices`

### Ключ upsert

Существующий документ ищется по паре:

- поставщик (`sellerCode` / `alias`);
- номер инвойса поставщика (`supplierNumber` → `НомерИнвойсаПоставщика`).

| Ситуация                                    | Поведение                                                            |
| ------------------------------------------- | -------------------------------------------------------------------- |
| Не найден                                   | Создаётся новый `Инвойс`, проводится                                 |
| Найден, **нет** приходных по `Инвойсу`      | Полная перезапись шапки и ТЧ `Товары`, проведение (`replaced: true`) |
| Найден, есть приходная (в т.ч. проведённая) | **400**, замена запрещена                                            |

### Поля заголовка

| Поле JSON | Синонимы | Обязательный | Описание |
|-----------|----------|--------------|----------|
| `sellerCode` | `supplierCode`, `code` | да\* | Код поставщика (`Контрагенты.Код`) |
| `alias` | `seller`, `supplier` | да\* | Псевдоним или наименование поставщика |
| `currency` | | да | Код валюты (`Валюты.Код` или `КодISO`) |
| `supplierNumber` | `supplierNo`, `invoiceNumber`, `invoiceNo` | да | Номер инвойса поставщика |
| `supplierDate` | `invoiceDate` | да | Дата инвойса поставщика (`yyyy-MM-dd`) |
| `date` | | нет | Дата документа; по умолчанию — текущая дата сеанса |
| `discount` | | нет | Скидка шапки (`ВКД_Скидка`) |
| `local` | | нет | Признак «Локал» (`Локал`). JSON-булево или строки `true`/`false`/`1`/`0`/`yes`/`no` |
| `inspectionDate` | | нет | Дата инспекции (`ДатаИнспекции`), `yyyy-MM-dd`; пустая строка сбрасывает |
| `eta` | | нет | Дата на складе отправителя (`ДатаНаСкладеОтправителя`), `yyyy-MM-dd`; пустая строка сбрасывает |
| `localStatus` | | нет | Локальный статус (`ЛокальныйСтатус`): английский синоним `СтатусыИнвойса` (см. ниже) |
| `deliveryFee` | | нет | Сумма доставки (`СуммаДоставки`) |
| `managerCode` | | нет | Код сотрудника (`Сотрудники.Код`) → реквизит `Менеджер`. Пустая строка сбрасывает |
| `note` | `comment` | нет | Примечание (`Примечание`, до 200 символов). Пустая строка сбрасывает |
| `attachment` | | нет | Массив вложений `{fileName, fileContent}` (см. ниже) |
| `items` | | да | Массив позиций |

\* Нужен хотя бы один идентификатор поставщика (`sellerCode` / `alias` и синонимы).

Если необязательное поле шапки **не передано**, при создании остаётся значение по умолчанию, при замене (upsert) — прежнее значение документа. Пустая строка `localStatus` / `inspectionDate` / `eta` / `managerCode` / `note` сбрасывает реквизит.

`managerCode` — числовой код справочника `Сотрудники`. Берётся первый найденный элемент (не группа): сначала с пустой датой увольнения, затем без пометки удаления. Поле `manager` на вход **не** принимается (только в ответе).

`note` (синоним `comment`) пишется в общий реквизит `Примечание` (до 200 символов). Если на **создании** поле не передано — `API invoice <имя учётной записи>`. На замене и PUT без `note` прежнее примечание не меняется.

### Локальный статус (`localStatus`)

Значения — **английские** синонимы перечисления `СтатусыИнвойса` (без учёта регистра). Допустимы также имена значений метаданных (`НеОтправлен`, `ВПути`, `ЧастичноПрибыл`, `Прибыл`).

| `localStatus` | Значение 1С |
|---------------|-------------|
| `Not shipped` | `НеОтправлен` |
| `In transit` | `ВПути` |
| `Partially received` | `ЧастичноПрибыл` |
| `Received` | `Прибыл` |

### Позиции `items[]`

> [!attention] Внимание
> Серии **не** поддерживаются.

| Поле | Синонимы | Обязательный | Описание |
|------|----------|--------------|----------|
| `itemCode` | `code` | да\* | Код номенклатуры |
| `itemSku` | `sku`, `SKU` | да\* | SKU |
| `itemUpc` | `upc`, `UPC` | да\* | UPC |
| `itemJan` | `jan`, `JAN`, `jan13`, `JAN13` | да\* | JAN13 |
| `item` | `name` | да\* | Наименование (точное / неточное) |
| `qty` | `quantity`, `count` | да | Количество (> 0) |
| `price` | `purchasePrice` | да\*\* | Цена в валюте инвойса |
| `amount` | `sum`, `purchaseAmount` | да\*\* | Сумма в валюте инвойса |

\* Нужен хотя бы один способ найти номенклатуру.  
\*\* Нужны `price` и/или `amount`. Если задано только одно — второе считается из `qty`.

Тип номенклатуры — только «Товар».

### Прикреплённые файлы

**POST** и **PUT** принимают массив вложений. **GET** и **DELETE** файлы не принимают и не возвращают.

Можно прикрепить **несколько** файлов к документу `Инвойс`. 

#### Поля элемента `attachment[]`

| Поле | Описание |
|------|----------|
| `fileName` | Имя с расширением: `invoice.pdf`, `scan.xls`, `photo.jpg` и т.п. Расширение **обязательно**. |
| `fileContent` | Содержимое в **base64** (для JSON или текстовой части multipart). |

#### Правила синхронизации

Сравнение с уже прикреплёнными в 1С файлами — по **имени без расширения + расширению** (без учёта регистра; пробелы нормализуются).

| Ситуация | Поведение |
|----------|-----------|
| Поле `attachment` отсутствует или массив пустой | Файлы в 1С **не меняются** |
| Элемент массива с тем же именем и расширением уже есть у `Инвойс` | Содержимое файла **заменяется** |
| Элемент с именем, которого нет у `Инвойс` | Файл **добавляется** |
| Файл есть в 1С, но его нет в `attachment` | Файл **остаётся без изменений** |
| В одном запросе несколько элементов с одним именем | Обрабатываются по порядку, побеждает последний |
| `attachment` не массив | **400** |
| В элементе нет `fileName` или нет содержимого | **400** |
| Некорректный base64 / пустой файл / нет расширения в имени | **400** |
| Документ сохранён, прикрепление не удалось | **400**, в теле — данные уже записанного инвойса (`number`, `items`, …) и текст ошибки |

Порядок на сервере: сначала проверка массива `attachment`, затем запись и проведение `Инвойс`, затем прикрепление файлов (вне транзакции документа). Ошибка разбора массива документ не создаёт и не меняет. При ошибке записи файла на диск документ в базе **остаётся**.

#### Способ 1 — JSON (`Content-Type: application/json`)

Все поля инвойса и массив `attachment` — один JSON-объект (см. пример выше).

#### Способ 2 — `multipart/form-data`

Заголовок: `Content-Type: multipart/form-data; boundary=...`

Варианты передачи данных:

1. **Часть `json` / `payload` / `data`** — JSON-объект с полями инвойса (`sellerCode`, `items`, `attachment`, …).
2. **Текстовые части** — те же поля, что в JSON, как отдельные поля формы (кроме `items`: массив удобнее передавать в части `json`). Поле `attachment` можно передать JSON-строкой массива.
3. **Файлы** — одна или несколько бинарных частей:
   - имя поля `attachment` или `file` и `filename="..."` в `Content-Disposition` (имя файла берётся из заголовка части);
   - бинарные части **добавляются** к массиву `attachment` из JSON, не заменяют его.

Пример (схематично):

```http
POST /trade/hs/stock/invoices
Content-Type: multipart/form-data; boundary=----boundary
X-Api-Key: your-api-token-here

------boundary
Content-Disposition: form-data; name="json"

{"sellerCode":"1201","currency":"USD","supplierNumber":"INV-7788","supplierDate":"2026-08-25","items":[{"itemCode":"10045","qty":2,"price":350.5}]}
------boundary
Content-Disposition: form-data; name="attachment"; filename="invoice-7788.pdf"
Content-Type: application/pdf

<бинарное содержимое PDF>
------boundary
Content-Disposition: form-data; name="attachment"; filename="packing-list.xls"
Content-Type: application/vnd.ms-excel

<бинарное содержимое XLS>
------boundary--
```

#### Типичные ошибки вложения (400)

| Текст / смысл |
|---------------|
| `Поле attachment должно быть массивом.` |
| `Вложение N: элемент attachment должен быть объектом.` |
| `Вложение N: укажите fileName вместе с содержимым файла.` |
| `Вложение N: укажите fileContent (base64) или передайте бинарную часть файла.` |
| `Вложение N: некорректный fileContent: ожидается base64.` |
| `Вложение N: пустое содержимое файла.` |
| `Вложение N: fileName должен содержать расширение (например invoice.pdf).` |
| `Не удалось прикрепить файл к инвойсу.` |

|------|----------|
| `replaced` | `true`, если выполнен upsert существующего инвойса |
| `amount` | Сумма документа (`Сумма`, в валюте учёта закупки с учётом курса) |
| `price` в `items` | `ЦенаИнвойса` (валюта инвойса) |
| `productRange` в `items` | Наименование ассортимента номенклатуры; пустая строка, если не заполнен |

Сведений о прикреплённых файлах в ответ нет. Пустая `ДатаИнспекции` / `ДатаНаСкладеОтправителя` / незаполненный `ЛокальныйСтатус` / `Менеджер` в ответе — пустые строки. `note` — текущее `Примечание`. `eta` — `ДатаНаСкладеОтправителя`.

### Ошибки

| HTTP | Когда |
|------|--------|
| **401** | Нет / неверный `X-Api-Key` |
| **400** | Ошибка валидации; поставщик/товар/валюта/сотрудник не найдены; некорректные `discount` / `deliveryFee` / `inspectionDate` / `eta` / `localStatus` / `managerCode`; ошибка массива `attachment` (до записи документа); есть приходная по инвойсу; сбой проведения; ошибка записи файла после проведения (документ при этом уже записан) |
| **500** | Непредвиденная ошибка сервера |

```json
{
  "success": false,
  "error": "Текст ошибки"
}
```

При блокировке замены из‑за приходной в теле дополнительно могут быть заполнены реквизиты найденного инвойса (`number`, `date`, `items` и т.д.).

### Поведение в 1С

1. Создаётся или открывается `Инвойс`.
2. При замене: отмена проведения (если был проведён), очистка `ВКД_Товары` и `Поставки`, перезапись шапки и строк.
3. Необязательные поля шапки (`discount`, `local`, `inspectionDate`, `eta`, `localStatus`, `deliveryFee`, `managerCode`, `note`) пишутся, только если переданы.
4. Цены запроса — в валюте инвойса (`ЦенаИнвойса`); `ЦенаЗакупки` / `СуммаЗакупки` пересчитываются по курсу на дату документа (для базовой валюты курс = 1).
5. Документ **проводится**.
6. Если передан непустой `attachment[]` — файлы прикрепляются к `Инвойс` (совпадение имени и расширения — замена; файлы, которых нет в массиве, не удаляются).

## PUT `/invoices`

**Назначение:** добавить позиции `items` к существующему инвойсу (аналог **PUT `/orders`**). Необязательные поля шапки (`discount`, `local`, `inspectionDate`, `eta`, `localStatus`, `deliveryFee`, `managerCode`, `note`) при передаче **обновляются**; если не переданы — шапка по ним не меняется. Пустая строка `managerCode` сбрасывает `Менеджер`, пустая `note` — `Примечание`, пустая `eta` / `inspectionDate` — соответствующую дату. Если передан `currency` — валюта и курс шапки обновляются; иначе остаются у документа. Цены позиций — в валюте инвойса.

**Запрос:**  
`PUT /trade/hs/stock/invoices`  
`Content-Type: application/json` или `multipart/form-data`

Массив `attachment[]` принимается так же, как у **POST**: замена по имени и расширению, файлы вне массива не меняются. PUT по-прежнему требует непустой `items`.

Идентификация документа (тело JSON и/или query-параметры URL) — нужен хотя бы один номер:

| Поле             | Синонимы                                   | Описание                                  |
| ---------------- | ------------------------------------------ | ----------------------------------------- |
| `number`         | `documentNumber`                           | Номер документа `_Инвойс` в 1С            |
| `supplierNumber` | `supplierNo`, `invoiceNumber`, `invoiceNo` | Номер инвойса поставщика                  |
| `date`           |                                            | Дата документа (`yyyy-MM-dd`) — уточнение |
| `sellerCode`     | `supplierCode`, `code`                     | Код поставщика (уточнение)                |
| `alias`          | `seller`, `supplier`                       | Псевдоним поставщика (уточнение)          |
| `managerCode`    |                                            | Код сотрудника → `Менеджер` (опционально) |
| `eta`            |                                            | Дата на складе отправителя (опционально)  |

Необязательные поля шапки (`discount`, `local`, `inspectionDate`, `eta`, `localStatus`, `deliveryFee`, `managerCode`, `note`) и массив `attachment[]` — как у **POST**.

Документ должен быть в иерархии поставщиков учётной записи. Если по инвойсу уже есть **приходная** накладная — изменение запрещено (**400**, при проведённой приходной — **409**).

### Позиции `items[]`

Те же поля, что у **POST `/invoices`**: `itemCode` / `itemSku` / …, `qty`, `price` и/или `amount`. Серии не поддерживаются.

### Пример

Только JSON-тело:

```http
PUT /invoices
Content-Type: application/json
X-Api-Key: your-api-token-here
```

```json
{
  "number": "000001234",
  "managerCode": "5",
  "attachment": [
    {
      "fileName": "addendum.pdf",
      "fileContent": "<base64-содержимое файла>"
    }
  ],
  "items": [
    {
      "itemCode": "20010",
      "qty": 3,
      "price": 12
    }
  ]
}
```

Идентификация в query (тело — только `items`):

```http
PUT /invoices?supplierNumber=INV-7788&sellerCode=1201
Content-Type: application/json
X-Api-Key: your-api-token-here
```

```json
{
  "items": [
    {
      "itemSku": "CABLE-USBC",
      "qty": 2,
      "amount": 24
    }
  ]
}
```

Или по номеру поставщика в теле:

```json
{
  "supplierNumber": "INV-7788",
  "sellerCode": "1201",
  "items": [
    {
      "itemSku": "CABLE-USBC",
      "qty": 2,
      "amount": 24
    }
  ]
}
```

### Успешный ответ (200)

Те же поля, что у успешного **POST**, без `replaced`: `success`, `error`, `number`, `date`, `seller`, `sellerCode`, `manager`, `managerCode`, `currency`, `supplierNumber`, `supplierDate`, `posted`, `amount`, `discount`, `local`, `inspectionDate`, `localStatus`, `deliveryFee`, `note`, `eta`, `items` (полный состав после добавления).

### Ошибки PUT

| HTTP | Когда |
|------|--------|
| **401** | Нет / неверный `X-Api-Key` |
| **400** | Валидация; поставщик/товар/сотрудник не найдены; некорректный `managerCode` / `eta`; ошибка `attachment`; есть непроведённая приходная; сбой проведения |
| **404** | Инвойс не найден |
| **409** | Есть **проведённая** приходная накладная |
| **500** | Непредвиденная ошибка сервера |

### Поведение в 1С

1. Поиск `Инвойс` по номеру / номеру поставщика в рамках поставщиков учётной записи.
2. Проверка отсутствия приходной по `ВКД_Инвойс`.
3. При необходимости — отмена проведения.
4. Добавление строк в `ВКД_Товары` (цены в валюте инвойса, пересчёт закупки по курсу документа).
5. Если переданы `discount` / `local` / `inspectionDate` / `eta` / `localStatus` / `deliveryFee` / `managerCode` / `note` — запись в шапку.
6. Пересчёт итогов и проведение.
7. Если передан непустой `attachment[]` — файлы прикрепляются к `Инвойс` (совпадение имени и расширения — замена; файлы, которых нет в массиве, не удаляются).

## DELETE `/invoices`

**Назначение:** удалить позиции `items` из существующего инвойса (аналог **DELETE `/orders`**). Шапка документа не меняется. Поля `qty` и `price` в DELETE **не используются**: удаляются **все строки** указанной номенклатуры.

**Запрос:**  
`DELETE /trade/hs/stock/invoices`  
`Content-Type: application/json`

Прикреплённые файлы **не** принимаются.

Идентификация документа — как у **PUT `/invoices`** (тело JSON и/или query-параметры URL): нужен хотя бы один номер (`number` / `supplierNumber` и синонимы). Документ должен быть в иерархии поставщиков учётной записи.

| Сценарий | Поведение |
|----------|-----------|
| В `items` перечислены **все** номенклатуры инвойса | Пометка документа на удаление, `deleted: true`, `posted: false`. Состав ТЧ в базе не меняется |
| После удаления указанных номенклатур **строк не остаётся** | То же: пометка на удаление (пустой инвойс в базе не оставляется) |
| Указана **часть** позиций, строки остаются | Удаление строк `ВКД_Товары` (и связанных строк `Поставки`), перепроведение, `deleted: false` |
| Номенклатура из `items` **отсутствует** в инвойсе | **400**, документ не меняется |
| Нет номера документа / номера поставщика или пустой / не массив `items` | **400** |
| По инвойсу есть приходная накладная (в т.ч. непроведённая) | **409** |
| Инвойс не найден (в т.ч. уже помечен на удаление) | **404** |

### Позиции `items[]`

Достаточно идентификатора номенклатуры — те же поля, что у **POST `/invoices`**: `itemCode` / `itemSku` / `itemUpc` / `itemJan` / `item`. `qty` и `price` **не обязательны** и игнорируются.

### Пример

Только JSON-тело:

```http
DELETE /invoices
Content-Type: application/json
X-Api-Key: your-api-token-here
```

```json
{
  "number": "000001234",
  "items": [
    {
      "itemCode": "20010"
    }
  ]
}
```

Идентификация в query (тело — только `items`):

```http
DELETE /invoices?supplierNumber=INV-7788&sellerCode=1201
Content-Type: application/json
X-Api-Key: your-api-token-here
```

```json
{
  "items": [
    {
      "itemSku": "CABLE-USBC"
    }
  ]
}
```

Пометка всего инвойса на удаление — перечислить все номенклатуры документа:

```json
{
  "supplierNumber": "INV-7788",
  "items": [
    { "itemCode": "20010" },
    { "itemSku": "CABLE-USBC" }
  ]
}
```

### Успешный ответ (200)

Те же поля, что у успешного **PUT**, плюс `deleted`:

- частичное удаление: `deleted: false`, `items` — оставшийся состав;
- пометка на удаление: `deleted: true`, `posted: false`, `items` — состав на момент пометки (ТЧ не очищается).

### Ошибки DELETE

| HTTP | Когда |
|------|--------|
| **401** | Нет / неверный `X-Api-Key` |
| **400** | Валидация; товар не найден; номенклатура отсутствует в инвойсе; сбой записи |
| **404** | Инвойс не найден |
| **409** | Есть приходная накладная (проведённая или нет) |
| **500** | Непредвиденная ошибка сервера |

### Поведение в 1С

1. Поиск `Инвойс` по номеру / номеру поставщика в рамках поставщиков учётной записи.
2. Проверка отсутствия приходной по `ВКД_Инвойс` (созданной на основании).
3. Если в `items` все номенклатуры документа — `УстановитьПометкуУдаления(Истина)` без изменения ТЧ.
4. Иначе — отмена проведения, удаление строк `ВКД_Товары` (и `Поставки` с теми же `ИДСтроки`), пересчёт итогов и проведение.
5. Если после удаления строк не осталось — транзакция отменяется, документ помечается на удаление (как в п. 3).
