# StockAPI — Приходная накладная (`/incomingwaybiils`)

HTTP-сервис **StockAPI**: создание приходных накладных (документ `ПриходнаяНакладная`, eng. *Incoming waybill*).

---

## Авторизация

```
X-Api-Key: <токен учётной записи интеграции>
```

Неактивная или неизвестная учётная запись → **401**.

Ограничения учётной записи:
- **склады** — ТЧ «Склады»;
- **поставщики** — иерархии групп из ТЧ «Поставщики».

Тело запроса и ответа — **JSON**, UTF-8. Даты: `yyyy-MM-dd` (в ответе — `yyyy-MM-ddTHH:mm:ss`).

---

## POST `/incomingwaybiils`

**Назначение:** создать и провести приходную накладную с партиями и остатками (флаг «Окончательно»).

**Запрос:**  
`POST /trade/hs/stock/incomingwaybiils`

### Поля заголовка документа

| Поле JSON | Синонимы | Обязательный | Описание |
|-----------|----------|--------------|----------|
| `sellerCode` | `supplierCode`, `code` | да\* | Код поставщика (`Контрагенты.Код`) |
| `alias` | `seller`, `supplier` | да\* | Псевдоним или наименование поставщика |
| `warehouseCode` | `warehouseId` | да\*\* | Код склада |
| `warehouse` | | да\*\* | Наименование склада |
| `currency` | | да | Код валюты (`Валюты.Код` или `КодISO`) |
| `supplierNumber` | `supplierNo`, `incomingNumber`, `incomingNo`, `incoming` | нет | Номер поставщика (`НомерПоставщика`); при повторе для того же поставщика — ошибка |
| `supplierDate` | `incomingDate` | нет | Дата поставщика (`ДатаПоставщика`), по умолчанию — дата документа |
| `date` | | нет | Дата документа; по умолчанию — текущая дата сеанса |
| `note` | `comment` | нет | Примечание (до 200 символов) |
| `items` | | да | Массив позиций |

\* Нужен хотя бы один идентификатор поставщика (`sellerCode` / `alias` и синонимы).  
\*\* Нужен код или наименование склада.

Поставщик ищется **только** среди элементов в иерархии групп из ТЧ «Поставщики» текущей учётной записи (см. также `GET /sellers`).

### Позиции `items[]`

| Поле | Синонимы | Обязательный | Описание |
|------|----------|--------------|----------|
| `itemCode` | `code` | да\* | Код номенклатуры |
| `item` | `name` | да\* | Наименование номенклатуры |
| `price` | `purchasePrice` | да | Цена закупки |
| `qty` | `quantity`, `count` | да\*\* | Количество (для несерийного товара) |
| `serial` | `series`, `imei` | да\*\*\* | Одна серия |
| `serials` | | да\*\*\* | Массив серий (каждая → отдельная строка с `qty = 1`) |

\* `itemCode` или `item`.  
\*\* Для товара **без** учёта по сериям.  
\*\*\* Для товара **с** учётом по сериям: `serial` и/или `serials`; количество всегда 1 на серию.

Тип номенклатуры — только «Товар». Повторяющиеся серии в одном запросе отклоняются.

### Ошибки

| HTTP | Когда |
|------|--------|
| **401** | Нет / неверный `X-Api-Key` |
| **400** | Ошибка валидации, поставщик/склад/товар не найдены, повтор `supplierNumber`, сбой проведения |
| **500** | Непредвиденная ошибка сервера |

Тело ошибки:

```json
{
  "success": false,
  "error": "Текст ошибки"
}
```

При повторном `supplierNumber` для того же поставщика в ответе дополнительно заполняются реквизиты уже существующей накладной (`number`, `date`, `items` и т.д.).

### Поведение в 1С

1. Создаётся `ПриходнаяНакладная` с заполненными шапкой и ТЧ «Товары».
2. Для каждой строки создаётся элемент справочника `Партии` (как при ручном вводе в форме).
3. Документ записывается с флагом **Окончательно** и **проводится** — формируются остатки, поставки, долг поставщику, цены закупки.
4. Связь с инвойсом закупки (`ВКД_Инвойс`) **не** заполняется: это прямой приход со стороны API.
