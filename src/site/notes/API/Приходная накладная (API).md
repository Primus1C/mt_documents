# StockAPI — Приходная накладная (`/incomingwaybiils`)

HTTP-сервис **StockAPI**: создание приходных накладных (документ `ПриходнаяНакладная`, eng. *Incoming waybill*).

---

## Авторизация

```
X-Api-Key: <токен учётной записи интеграции>
```

Неактивная или неизвестная учётная запись → **401**.

Ограничения учётной записи:
- **склады** — ТЧ «Склады»;
- **поставщики** — иерархии групп из ТЧ «Поставщики».

Тело запроса и ответа — **JSON**, UTF-8. Даты: `yyyy-MM-dd` (в ответе — `yyyy-MM-ddTHH:mm:ss`).

---

## Эндпоинты

| Метод | URL | Назначение |
|-------|-----|------------|
| GET | `/incomingwaybiils` | Одна приходная или список с пагинацией |
| POST | `/incomingwaybiils` | Создание и проведение приходной |

---

## Пагинация (GET)

| Параметр | Синоним | Описание |
|----------|---------|----------|
| `page` | — | Номер страницы, с 1 (по умолчанию 1) |
| `pageSize` | `limit` | Размер страницы, 1–500 (по умолчанию 500) |

Ответ всегда содержит: `page`, `pageSize`, `totalItems`, `totalPages`, `items[]`.

---

## GET `/incomingwaybiils`

**Назначение:** получить одну приходную накладную или список (поставщики из ТЧ «Поставщики» учётной записи). Параметры и проверки — **как у `GET /invoices`**.

**Запрос:**  
`GET /trade/hs/stock/incomingwaybiils?...`

### Режим одного документа

Указан номер документа 1С и/или номер поставщика:

```
GET /incomingwaybiils?number=000001234
GET /incomingwaybiils?supplierNumber=INV-7788
GET /incomingwaybiils?number=000001234&date=2026-08-25
GET /incomingwaybiils?supplierNumber=INV-7788&sellerCode=1201
```

| Параметр | Синонимы | Описание |
|----------|----------|----------|
| `number` | `invoiceNumber`, `invoiceNo` | Номер документа `ПриходнаяНакладная` в 1С |
| `supplierNumber` | `supplierNo` | Номер поставщика (`НомерПоставщика`) |
| `date` | `invoiceDate` | Дата документа (`yyyy-MM-dd`) — уточнение |
| `sellerCode` | `supplierCode`, `code` | Код поставщика (опционально) |
| `alias` | `seller`, `supplier` | Псевдоним поставщика (опционально) |

Достаточно одного из номеров. Помеченные на удаление не возвращаются → **404**. Несколько совпадений → **400**.

### Режим списка

Номер не указан. Фильтр по поставщику и/или периоду:

```
GET /incomingwaybiils?sellerCode=1201&dateFrom=2026-08-01&dateTo=2026-08-31&page=1&pageSize=50
GET /incomingwaybiils?dateFrom=2026-08-01&dateTo=2026-08-31
```

| Параметр | Синонимы | Описание |
|----------|----------|----------|
| `sellerCode` | `supplierCode`, `code` | Код поставщика |
| `alias` | `seller`, `supplier` | Псевдоним / наименование |
| `dateFrom` | `from` | Начало периода (`yyyy-MM-dd`) |
| `dateTo` | `to` | Конец периода (`yyyy-MM-dd`) |

Период `dateFrom`/`dateTo` — **парой**; иначе **400**.

### Успешный ответ (200)

Дополнительно к полям накладной — данные инвойса-основания (`ВКД_Инвойс` / `_Инвойс`):

| Поле | Источник |
|------|----------|
| `invoiceNumber` | `_Инвойс.Номер` (номер 1С) |
| `invoiceIncomingNumber` | `_Инвойс.ВКД_НомерИнвойсаПоставщика` |
| `invoiceDate` | `_Инвойс.Дата` |

Если основание не заполнено — эти поля пустые строки.

```json
{
  "page": 1,
  "pageSize": 50,
  "totalItems": 1,
  "totalPages": 1,
  "items": [
    {
      "number": "000001234",
      "date": "2026-08-25T15:40:00",
      "seller": "Supplier Ltd",
      "sellerCode": "1201",
      "warehouse": "Main",
      "warehouseCode": "1",
      "currency": "USD",
      "supplierNumber": "INV-7788",
      "supplierDate": "2026-08-25T00:00:00",
      "posted": true,
      "amount": 973.5,
      "invoiceNumber": "000000555",
      "invoiceIncomingNumber": "INV-7788",
      "invoiceDate": "2026-08-24T10:00:00",
      "items": [
        {
          "item": "iPhone 15",
          "itemCode": "10045",
          "qty": 1,
          "price": 350.5,
          "amount": 350.5,
          "serial": "356938035643809"
        }
      ]
    }
  ]
}
```

### Ошибки GET

| HTTP | Когда |
|------|--------|
| **401** | Нет / неверный `X-Api-Key` |
| **400** | Некорректные параметры; несколько документов |
| **404** | Документ не найден |
| **500** | Непредвиденная ошибка |

## POST `/incomingwaybiils`

**Назначение:** создать и провести приходную накладную с партиями и остатками (флаг «Окончательно»).

**Запрос:**  
`POST /trade/hs/stock/incomingwaybiils`

### Поля заголовка документа

| Поле JSON               | Синонимы                                                 | Обязательный | Описание                                                                                                                       |
| ----------------------- | -------------------------------------------------------- | ------------ | ------------------------------------------------------------------------------------------------------------------------------ |
| `sellerCode`            | `supplierCode`, `code`                                   | да\*         | Код поставщика (`Контрагенты.Код`)                                                                                             |
| `alias`                 | `seller`, `supplier`                                     | да\*         | Псевдоним или наименование поставщика                                                                                          |
| `warehouseCode`         | `warehouseId`                                            | да\*\*       | Код склада                                                                                                                     |
| `warehouse`             |                                                          | да\*\*       | Наименование склада                                                                                                            |
| `currency`              |                                                          | да           | Код валюты (`Валюты.Код` или `КодISO`)                                                                                         |
| `supplierNumber`        | `supplierNo`, `incomingNumber`, `incomingNo`, `incoming` | нет          | Номер поставщика (`НомерПоставщика`); при повторе для того же поставщика — ошибка                                              |
| `supplierDate`          | `incomingDate`                                           | нет          | Дата поставщика (`ДатаПоставщика`), по умолчанию — дата документа                                                              |
| `date`                  |                                                          | нет          | Дата документа; по умолчанию — текущая дата сеанса                                                                             |
| `note`                  | `comment`                                                | нет          | Примечание (до 200 символов)                                                                                                   |
| `invoiceNumber`         | `invoiceNo`                                              | нет          | Связь с инвойсом закупки (`ВКД_Инвойс`): номер `_Инвойс` в 1С **или** номер инвойса поставщика (см. ниже)                      |
| `invoiceSupplierNumber` | `invoiceSupplierNo`                                      | нет          | Номер инвойса поставщика (`Инвойс.ВКД_НомерИнвойсаПоставщика`); можно указать вместе с `invoiceNumber` для однозначного поиска |
| `items`                 |                                                          | да           | Массив позиций                                                                                                                 |

\* Нужен хотя бы один идентификатор поставщика (`sellerCode` / `alias` и синонимы).  
\*\* Нужен код или наименование склада.

Поставщик ищется **только** среди элементов в иерархии групп из ТЧ «Поставщики» текущей учётной записи (см. также `GET /sellers`).

> **Не путать с GET:** в query-параметрах GET `invoiceNumber` / `invoiceNo` — синонимы номера **приходной** (`number`). В теле POST `invoiceNumber` относится к документу **`_Инвойс`**, а `supplierNumber` — к номеру **приходной у поставщика** (`НомерПоставщика`).

### Связь с инвойсом закупки (POST, необязательно)

Если **`invoiceNumber`** и **`invoiceSupplierNumber`** не переданы — реквизит `ВКД_Инвойс` приходной **не заполняется** (как при прямом приходе без инвойса).

Если передан хотя бы один из параметров:

- поиск `Инвойс` выполняется среди инвойсов поставщиков учётной записи;
- контрагент инвойса должен совпадать с **поставщиком** приходной из запроса;
- только **`invoiceNumber`**: сначала по номеру документа 1С (`Инвойс.Номер`), при отсутствии — по номеру инвойса поставщика (`ВКД_НомерИнвойсаПоставщика`);
- **`invoiceNumber`** и **`invoiceSupplierNumber`** вместе — оба условия (как при точечном поиске в API инвойсов);
- инвойс не найден или найдено несколько → **400**, документ не создаётся;
- при успехе в шапке приходной заполняется **`ВКД_Инвойс`**.

Параметра **`invoiceDate`** в POST **нет** (дата связанного инвойса возвращается только в GET в поле `invoiceDate`).

### Позиции `items[]`

| Поле | Синонимы | Обязательный | Описание |
|------|----------|--------------|----------|
| `itemCode` | `code` | да\* | Код номенклатуры |
| `item` | `name` | да\* | Наименование номенклатуры |
| `price` | `purchasePrice` | да | Цена закупки |
| `qty` | `quantity`, `count` | да\*\* | Количество (для несерийного товара) |
| `serial` | `series`, `imei` | да\*\*\* | Одна серия |
| `serials` | | да\*\*\* | Массив серий (каждая → отдельная строка с `qty = 1`) |

\* `itemCode` или `item`.  
\*\* Для товара **без** учёта по сериям.  
\*\*\* Для товара **с** учётом по сериям: `serial` и/или `serials`; количество всегда 1 на серию.

Тип номенклатуры — только «Товар». Повторяющиеся серии в одном запросе отклоняются.

### Ошибки

| HTTP | Когда |
|------|--------|
| **401** | Нет / неверный `X-Api-Key` |
| **400** | Ошибка валидации, поставщик/склад/товар не найдены, повтор `supplierNumber`, инвойс по `invoiceNumber` / `invoiceSupplierNumber` не найден или неоднозначен, сбой проведения |
| **500** | Непредвиденная ошибка сервера |

Тело ошибки:

```json
{
  "success": false,
  "error": "Текст ошибки"
}
```

При повторном `supplierNumber` для того же поставщика в ответе дополнительно заполняются реквизиты уже существующей накладной (`number`, `date`, `items` и т.д.).

### Поведение в 1С

1. Создаётся `ПриходнаяНакладная` с заполненными шапкой и ТЧ «Товары».
2. Для каждой строки создаётся элемент справочника `Партии` (как при ручном вводе в форме).
3. Документ записывается с флагом **Окончательно** и **проводится** — формируются остатки, поставки, долг поставщику, цены закупки.
4. Реквизит **`ВКД_Инвойс`** заполняется только если в запросе указаны `invoiceNumber` и/или `invoiceSupplierNumber` и инвойс найден однозначно; иначе остаётся пустым.
