# StockAPI — Замена проданного товара (`/replace`)

HTTP-сервис **StockAPI**: документ `ЗаменаПроданногоТовара` (*Sold goods replacement*).

Возврат серии из расходной накладной на склад и выдача другой серии взамен (остатки + сторно/повтор продажи без изменения денежной суммы). Документ **проводится**.

---

## Авторизация

```
X-Api-Key: <токен учётной записи интеграции>
```

Неактивная или неизвестная учётная запись → **401**.

Ограничения учётной записи:
- **склады** — ТЧ «Склады» (склад берётся из РН-основания и должен быть разрешён);
- **контрагенты (покупатели)** — иерархии групп из ТЧ «Контрагенты»;
- расходная накладная должна быть связана с заказом (`ИнвойсПродажи`) этой учётной записи;
- **сотрудник** — по настройкам ТЧ «ИдентификацияСотрудников» для метода `replacePOST` (`employeeCode` / `employeePin`).

Тело запроса и ответа — **JSON**, UTF-8. Даты: `yyyy-MM-dd` (в ответе — `yyyy-MM-ddTHH:mm:ss`).

---

## Эндпоинты

| Метод | URL | Назначение |
|-------|-----|------------|
| GET | `/replace` | Одна замена или список с пагинацией |
| POST | `/replace` | Создание или перезаполнение и проведение замены |

Базовый путь: `/trade/hs/stock/replace`.

---

## Пагинация (GET)

| Параметр | Синоним | Описание |
|----------|---------|----------|
| `page` | — | Номер страницы, с 1 (по умолчанию 1) |
| `pageSize` | `limit` | Размер страницы, 1–500 (по умолчанию 500) |

Ответ всегда содержит: `page`, `pageSize`, `totalItems`, `totalPages`, `items[]`.

## GET `/replace`

**Назначение:** получить один документ замены или список. Параметры и проверки — **как у `GET /invoices`**, с учётом особенностей объекта.

**Запрос:**  
`GET /trade/hs/stock/replace?...`

### Режим одного документа

Указан номер замены и/или номер расходной накладной:

```
GET /replace?number=000000123
GET /replace?deliveryNumber=000000456
GET /replace?number=000000123&date=2026-09-01
GET /replace?deliveryNumber=000000456&sellerCode=1201
```

| Параметр | Синонимы | Описание |
|----------|----------|----------|
| `number` | `replaceNumber`, `replaceNo` | Номер документа `ЗаменаПроданногоТовара` в 1С |
| `deliveryNumber` | `deliveryNo`, `delivery` | Номер расходной накладной-основания |
| `date` | — | Дата документа (`yyyy-MM-dd`) — уточнение |
| `sellerCode` | `customerCode`, `counterpartyCode`, `code` | Код покупателя (опционально) |
| `alias` | `seller`, `customer`, `counterparty`, `name` | Псевдоним / наименование покупателя |

Достаточно одного из номеров. Помеченные на удаление не возвращаются → **404**. Несколько совпадений → **400**.

### Режим списка

Номер не указан. Фильтр по покупателю и/или периоду:

```
GET /replace?sellerCode=1201&dateFrom=2026-08-01&dateTo=2026-08-31&page=1&pageSize=50
GET /replace?dateFrom=2026-08-01&dateTo=2026-08-31
```

| Параметр | Синонимы | Описание |
|----------|----------|----------|
| `sellerCode` | `customerCode`, `counterpartyCode`, `code` | Код покупателя |
| `alias` | `seller`, `customer`, `counterparty`, `name` | Псевдоним / наименование |
| `dateFrom` | `from` | Начало периода (`yyyy-MM-dd`) |
| `dateTo` | `to` | Конец периода (`yyyy-MM-dd`) |

Период `dateFrom`/`dateTo` — **парой**; иначе **400**.

### Успешный ответ (200)

```json
{
  "page": 1,
  "pageSize": 50,
  "totalItems": 1,
  "totalPages": 1,
  "items": [
    {
      "number": "000000123",
      "date": "2026-09-01T14:20:00",
      "deliveryNumber": "000000456",
      "orderNumber": "000000789",
      "incomingNumber": "ORD-100",
      "customer": "Buyer Ltd",
      "customerCode": "1201",
      "warehouse": "Main",
      "warehouseCode": "1",
      "posted": true,
      "items": [
        {
          "item": "iPhone 15 128 Black",
          "itemCode": "10001",
          "serial": "SN-RETURN-001",
          "itemReplace": "iPhone 15 128 Blue",
          "itemCodeReplace": "10002",
          "serialReplace": "SN-OUT-002"
        }
      ]
    }
  ]
}
```

| Поле | Описание |
|------|----------|
| `number` | Номер документа замены |
| `deliveryNumber` | Номер РН-основания |
| `orderNumber` / `incomingNumber` | Номер заказа 1С / входящий номер заказа |
| `customer` / `customerCode` | Покупатель |
| `warehouse` / `warehouseCode` | Склад (из РН) |
| `posted` | Проведён |
| `items[]` | Пары: возврат (`item*` + `serial`) и выдача взамен (`item*Replace` + `serialReplace`) |

Ошибки: **400** (некорректные параметры), **404** (не найден).

## POST `/replace`

**Назначение:** создать документ замены по расходной накладной или **перезаполнить** уже существующий по той же РН (отмена проведения → очистка ТЧ → заполнение → проведение).

**Запрос:**  
`POST /trade/hs/stock/replace`

### Тело

```json
{
  "deliveryNumber": "000000456",
  "date": "2026-09-01",
  "employeeCode": "12",
  "employeePin": "1234",
  "items": [
    {
      "itemCode": "10001",
      "serial": "SN-RETURN-001",
      "itemCodeReplace": "10002",
      "serialReplace": "SN-OUT-002"
    }
  ]
}
```

| Поле | Синонимы | Обязательно | Описание |
|------|----------|-------------|----------|
| `deliveryNumber` | `delivery`, `deliveryNo` | да | Номер **расходной накладной** |
| `items` | — | да | Массив пар замены |
| `date` | — | нет | Дата документа (`yyyy-MM-dd`); по умолчанию — текущая |
| `employeeCode` / `employeePin` | — | по настройкам УЗ | Идентификация сотрудника |

#### Элемент `items[]`

| Поле | Синонимы | Обязательно | Описание |
|------|----------|-------------|----------|
| `itemCode` или `item` | — | да | Товар **возврата** (из РН) |
| `serial` | `serialNumber` | да | Серия возврата; должна быть в РН; **партия** берётся из строки РН |
| `itemCodeReplace` или `itemReplace` | `replaceItemCode`, `itemCodeOut` / `replaceItem`, `itemOut` | да | Товар **выдачи взамен** |
| `serialReplace` | `replaceSerial`, `serialOut` | да | Серия выдачи; **партия** ищется на складе РН по остаткам автоматически |

Правила:
- склад и контрагент — из РН;
- РН должна быть **проведена**;
- серия возврата обязана входить в РН и соответствовать указанному товару;
- серия выдачи должна однозначно найтись на складе РН с остатком ≥ 1 для указанной номенклатуры;
- повторный POST по той же РН **перезаполняет** существующий документ (`replaced: true`).

### Успешный ответ (200)

```json
{
  "success": true,
  "error": "",
  "number": "000000123",
  "date": "2026-09-01T14:20:00",
  "deliveryNumber": "000000456",
  "orderNumber": "000000789",
  "incomingNumber": "ORD-100",
  "customer": "Buyer Ltd",
  "customerCode": "1201",
  "warehouse": "Main",
  "warehouseCode": "1",
  "posted": true,
  "replaced": false,
  "items": [
    {
      "item": "iPhone 15 128 Black",
      "itemCode": "10001",
      "serial": "SN-RETURN-001",
      "itemReplace": "iPhone 15 128 Blue",
      "itemCodeReplace": "10002",
      "serialReplace": "SN-OUT-002"
    }
  ]
}
```

| Поле       | Описание                                                                                 |
| ---------- | ---------------------------------------------------------------------------------------- |
| `replaced` | `true`, если перезаполнен уже существовавший документ замены по этой Расходной накладной |

### Ошибки

| Код | Когда |
|-----|--------|
| **400** | Нет `deliveryNumber` / `items`, серии не в РН, нет остатка для выдачи, склад/контрагент недоступны, ошибка проведения |
| **401** | Неверный API-ключ |
| **404** | Расходная накладная не найдена |
