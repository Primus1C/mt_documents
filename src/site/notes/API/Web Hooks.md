# Web Hooks

Исходящие уведомления из 1С во внешние системы при изменении **остатков**, **цен продажи** и **перечислимого статуса заказа** (`ИнвойсПродажи`).

Настройка выполняется в [[Справочники (НСИ)/Учетные записи интеграции\|учётных записях интеграции]]. Доставка — асинхронная: события попадают в регистр **`ОчередьWebHook`**, отправку выполняет регламентное задание **`WebHooksStockAPI`**.

> [!note]
> Тип события **`Наличие`** в конфигурации **не реализован**. Поддерживаются только `Остаток`, `Цена` и `СтатусЗаказа`.

---

## Настройка учётной записи

| Реквизит | Назначение |
| --- | --- |
| `WebhookАктивен` | Включить исходящие webhook для записи |
| `WebhookURL` | URL приёмника (обязателен при активном webhook; схема `http://` или `https://`) |
| `WebhookToken` | Секрет для заголовка `Authorization: Bearer …` |
| `ОтправлятьОстатки` | Участвовать в событиях `Остаток` |
| `ОтправлятьЦены` | Участвовать в событиях `Цена` |

Дополнительные условия отправки:

1. учётная запись **активна** (`Активен = Истина`);
2. `WebhookАктивен = Истина`;
3. заполнен **`WebhookURL`**;
4. для остатков — `ОтправлятьОстатки`; для цен — `ОтправлятьЦены`;
5. для **`СтатусЗаказа`** отдельный флаг не требуется — достаточно активного webhook у учётной записи заказа.

Склад события должен входить в табличную часть **«Склады»** учётной записи. Склад не должен быть помечен на удаление.

---

## Типы событий

Перечисление **`ТипыСобытийWebHooks`**. В JSON поле `eventType` — строковое представление значения перечисления.

| `eventType` | Когда ставится в очередь | Источник в 1С |
| --- | --- | --- |
| **`Остаток`** | Изменение движений по `ОстаткиТовара` или `РезервыТовара` | Подписка `WebHookОстатки` → `StockAPI_Остатки.WebHookОстаткиПередЗаписью` |
| **`Цена`** | Проведение или отмена проведения документа `УстановкаЦен` (в т. ч. через POST `/prices`) | `Documents/УстановкаЦен` |
| **`СтатусЗаказа`** | Смена ресурса **`Состояние`** регистра `СостоянияИнвойсовПродажи` | `РаботаСИнвойсами.ЗаписатьСтатусИнвойсаПродажи` → `StockAPI_Утилиты.ЗарегистрироватьWebHookСтатусЗаказа` |

### Что не создаёт webhook

- смена API-признаков заказа `Заблокирован`, `ОтмененЗакачиком`, `ГотовКОтгрузке` (**POST /status**) — меняются отдельные ресурсы регистра, **`Состояние` не меняется**;
- заказы без заполненной **`УчетнаяЗапись`** или с неактивной / без webhook учётной записи;
- цены, для которых уже есть более поздняя запись в `ЦеныПродажи` (отправляется актуальное состояние, промежуточное событие отбрасывается).

Подробнее о статусах заказа: [[Статусы1СИнвойсовПродажи\|Статусы1СИнвойсовПродажи]].

## Очередь и отправка

### Регистр `ОчередьWebHook`

Измерения записи: `ИД`, `УчетнаяЗапись`, `ТипСобытия`, `Номенклатура`, `Склад`, `ВидЦены`, `Валюта`, `Заказ`.

Ресурсы: `Создан`, `Отправлен`, `Инициатор`, `КоличествоПопыток`, `ПоследняяПопытка`, `Ошибка`.

- **`Отправлен`** — пустая дата (`01.01.0001`) означает «ещё не доставлено»;
- **`Инициатор`** — документ, вызвавший изменение (регистратор движения, `УстановкаЦен`, документ смены статуса);
- при повторном изменении того же ключа (учётная запись + тип + номенклатура/склад/… ) **неотправленная** запись **заменяется** новой.

### Регламентное задание

`WebHooksStockAPI` вызывает `StockAPI_Утилиты.ОтправкаWebHook` → `ОтправитьОчередьWebHook`.

За один запуск:

- обрабатывается до **100 HTTP-пакетов** (параметр `МаксимумЗаписей`);
- в одном пакете — до **200** элементов `items`;
- пакеты группируются по паре **учётная запись + тип события**.

### Повторные попытки

Интервалы между попытками (в секундах) задаются константой **`ПериодичностьОповещенийИнтеграции`**.

Значение по умолчанию, если константа пуста:

`30, 30, 30, 60, 60, 300, 600, 3600`

После исчерпания списка используется последний интервал. Ошибки записываются в ресурс **`Ошибка`** (до 500 символов). Успешной считается доставка с HTTP-кодом **2xx**.

---

## HTTP-запрос к приёмнику

```
POST <WebhookURL>
Content-Type: application/json; charset=utf-8
Accept: application/json
Authorization: Bearer <WebhookToken>
```

Таймаут соединения — **30 секунд**. Поддерживаются `http://` и `https://`.

### Ошибка 401

Приёмник вернёт **401**, если:

- заголовок `Authorization` отсутствует;
- формат не `Bearer <token>`;
- значение не совпадает с **`WebhookToken`** учётной записи.

Убедитесь, что в учётной записи интеграции заполнен **`WebhookToken`** тем же значением, которое ожидает сервер.

## Формат JSON (общая обёртка пакета)

```json
{
  "batchId": "a1b2c3d4-e5f6-7890-abcd-ef1234567890",
  "eventType": "Остаток",
  "createdAt": "2026-08-18T12:00:00",
  "items": [ /* см. ниже */ ]
}
```

| Поле | Описание |
| --- | --- |
| `batchId` | UUID пакета (генерируется при отправке) |
| `eventType` | `Остаток`, `Цена` или `СтатусЗаказа` |
| `createdAt` | Минимальная дата `Создан` среди элементов пакета, формат `yyyy-MM-ddTHH:mm:ss` |
| `items` | Массив событий одного типа |

---

## Элементы `items`

### Общие поля (остатки и цены)

| Поле | Описание |
| --- | --- |
| `eventId` | UUID записи очереди |
| `createdAt` | Дата постановки в очередь |
| `itemCode` | Код номенклатуры (число без разделителей групп) |
| `item` | Наименование номенклатуры |
| `warehouse` | Код склада |
| `warehouseName` | Наименование склада |
| `source` | Представление документа-инициатора (если заполнен) |

### `eventType: "Остаток"`

Дополнительные поля — **актуальные** остатки на момент отправки:

| Поле | Описание |
| --- | --- |
| `balance` | Свободный остаток (строка) |
| `reserve` | Резерв (строка) |

Пример:

```json
{
  "batchId": "…",
  "eventType": "Остаток",
  "createdAt": "2026-08-18T12:00:00",
  "items": [
    {
      "eventId": "…",
      "createdAt": "2026-08-18T12:00:01",
      "itemCode": "12345",
      "item": "Товар А",
      "warehouse": "1",
      "warehouseName": "Основной",
      "balance": "10",
      "reserve": "2",
      "source": "Инвойс продажи 00001234 от 18.08.2026"
    }
  ]
}
```

### `eventType: "Цена"`

| Поле | Описание |
| --- | --- |
| `priceType` | Наименование вида цены (`ВидыЦен`) |
| `currency` | Наименование валюты из регистра `ЦеныПродажи` |
| `price` | Массив ступеней цены: `{ "qty": <порог>, "price": <число> }` |

Ступени формируются из ресурсов регистра `ЦеныПродажи`: базовая цена (`qty = 1`), затем пороги `Порог1`…`Порог3` с ценами `Цена1`…`Цена3` (нулевые пропускаются).

Пример:

```json
{
  "batchId": "…",
  "eventType": "Цена",
  "createdAt": "2026-08-18T12:10:00",
  "items": [
    {
      "eventId": "…",
      "createdAt": "2026-08-18T12:10:01",
      "itemCode": "12345",
      "item": "Товар А",
      "warehouse": "1",
      "warehouseName": "Основной",
      "priceType": "Розница",
      "currency": "USD",
      "price": [
        { "qty": 1, "price": 1990.5 },
        { "qty": 10, "price": 1850 }
      ],
      "source": "Установка цен 00000045 от 18.08.2026"
    }
  ]
}
```

> [!warning]
> В отличие от упрощённых примеров тестового сервера, 1С передаёт **`price` массивом ступеней**, а не одной строкой/числом. Приёмник должен обрабатывать структуру регистра `ЦеныПродажи`.

### `eventType: "СтатусЗаказа"`

| Поле | Описание |
| --- | --- |
| `orderNumber` | Номер заказа в 1С |
| `incomingNumber` | Входящий номер (`НомерВходящий`) |
| `status` | Значение перечисления `СтатусыИнвойсаПродажи` (`Зарегистрирован`, `Изменен`, `Собирается`, `ГотовКОтгрузке`, `Отгружен`, `Отменен`) |
| `statusSetBy` | Кто изменил статус |
| `statusDate` | Дата регистрации статуса |
| `source` | Документ-инициатор смены статуса |

Пример:

```json
{
  "batchId": "…",
  "eventType": "СтатусЗаказа",
  "createdAt": "2026-08-18T12:20:00",
  "items": [
    {
      "eventId": "…",
      "createdAt": "2026-08-18T12:20:01",
      "orderNumber": "00001234",
      "incomingNumber": "WEB-9876",
      "status": "Отгружен",
      "statusSetBy": "Иванов И.И.",
      "statusDate": "2026-08-18T12:19:55",
      "source": "Расходная накладная 00000567 от 18.08.2026"
    }
  ]
}
```

Webhook отправляется **только** учётной записи, указанной в реквизите **`УчетнаяЗапись`** заказа.

## Диагностика

| Где смотреть | Что показывает |
| --- | --- |
| Регистр **`ОчередьWebHook`** (подсистема «Интеграция») | Неотправленные события, текст последней ошибки, число попыток |
| Журнал регистрации, событие **`StockAPI.WebHook`** | Ошибки регламентной отправки и постановки статуса заказа |
| [[webhook_test_server.txt\|webhook_test_server.txt]] | Пример тестового приёмника и заметки по проверке |

Типичные причины, почему событие не уходит:

- не включён **`WebhookАктивен`** или пуст **`WebhookURL`** / **`WebhookToken`**;
- для остатков/цен не установлены **`ОтправлятьОстатки`** / **`ОтправлятьЦены`**;
- склад не входит в ТЧ «Склады» учётной записи;
- заказ создан не через API (нет **`УчетнаяЗапись`**) — для **`СтатусЗаказа`**;
- приёмник отвечает не **2xx** — запись остаётся в очереди, повтор по расписанию.
