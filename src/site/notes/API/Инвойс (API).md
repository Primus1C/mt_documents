# StockAPI — Инвойс закупки (`/invoices`)

HTTP-сервис **StockAPI**: создание, замена, добавление позиций и чтение инвойсов закупки (документ `_Инвойс`, eng. *Purchase invoice*).

---

## Авторизация

```
X-Api-Key: <токен учётной записи интеграции>
```

Неактивная или неизвестная учётная запись → **401**.

Ограничения учётной записи:
- **поставщики** — иерархии групп из ТЧ «Поставщики» (см. `GET /sellers`).

Склады **не** используются.

### Формат запросов и ответов

| Метод | Тело запроса                                                                                      | Ответ       |
| ----- | ------------------------------------------------------------------------------------------------- | ----------- |
| GET   | —                                                                                                 | JSON, UTF-8 |
| POST  | `application/json` **или** `multipart/form-data` (см. [[#Прикреплённые файлы (POST `/invoices`)]] | JSON        |
| PUT   | `application/json`                                                                                | JSON        |

Даты в параметрах и теле: `yyyy-MM-dd`. В ответе: `yyyy-MM-ddTHH:mm:ss`.

### Сотрудник (опционально)

Для **POST** и **PUT** в учётной записи может быть включена обязательная идентификация сотрудника (настройки API). Тогда в теле или query нужен `employeeCode` или `employeePin`. Если настройка выключена — поля можно не передавать.

## Эндпоинты

| Метод | URL | Назначение |
|-------|-----|------------|
| GET | `/invoices` | Один инвойс или список с пагинацией |
| POST | `/invoices` | Создание или полная замена (upsert); опционально — прикрепление одного файла |
| PUT | `/invoices` | Добавление позиций в существующий инвойс (без изменения вложений) |

## Пагинация (GET `/invoices`)

| Параметр | Синоним | Описание |
|----------|---------|----------|
| `page` | — | Номер страницы, с 1 (по умолчанию 1) |
| `pageSize` | `limit` | Размер страницы, 1–500 (по умолчанию 500) |

Ответ всегда содержит: `page`, `pageSize`, `totalItems`, `totalPages`, `items[]`.

## GET `/invoices`

**Назначение:** получить один инвойс или список инвойсов поставщиков, доступных учётной записи.

**Запрос:**  
`GET /trade/hs/stock/invoices?...`

Ответ **всегда** в виде списка с пагинацией. Даже для одного документа в `items` будет один элемент.

### Режим одного инвойса

Указан номер документа 1С и/или номер инвойса поставщика:

```
GET /invoices?number=000001234
GET /invoices?supplierNumber=INV-7788
GET /invoices?number=000001234&date=2026-08-25
GET /invoices?supplierNumber=INV-7788&sellerCode=1201
```

| Параметр         | Синонимы                     | Описание                                                           |
| ---------------- | ---------------------------- | ------------------------------------------------------------------ |
| `number`         | `invoiceNumber`, `invoiceNo` | Номер документа `_Инвойс` в 1С                                     |
| `supplierNumber` | `supplierNo`                 | Номер инвойса поставщика (`ВКД_НомерИнвойсаПоставщика`)            |
| `date`           | `invoiceDate`                | Дата документа (`yyyy-MM-dd`) — уточнение при неоднозначном номере |
| `sellerCode`     | `supplierCode`, `code`       | Код поставщика (опционально)                                       |
| `alias`          | `seller`, `supplier`         | Псевдоним поставщика (опционально)                                 |

Достаточно одного из номеров (можно оба). Документ должен относиться к поставщику из ТЧ «Поставщики» учётной записи. Помеченные на удаление не возвращаются → **404**.

Если найдено несколько документов — **400** (уточните `date` и/или `sellerCode` / оба номера).

### Режим списка

Номер не указан. Фильтр по поставщику и/или периоду даты документа:

```
GET /invoices?sellerCode=1201&dateFrom=2026-08-01&dateTo=2026-08-31&page=1&pageSize=50
GET /invoices?dateFrom=2026-08-01&dateTo=2026-08-31
```

| Параметр | Синонимы | Описание |
|----------|----------|----------|
| `sellerCode` | `supplierCode`, `code` | Код поставщика |
| `alias` | `seller`, `supplier` | Псевдоним / наименование поставщика (как в POST) |
| `dateFrom` | `from` | Начало периода по дате документа (`yyyy-MM-dd`) |
| `dateTo` | `to` | Конец периода по дате документа (`yyyy-MM-dd`) |

Без `sellerCode`/`alias` — все инвойсы поставщиков из иерархии групп ТЧ «Поставщики» учётной записи. Период `dateFrom`/`dateTo` задаётся **парой**; при указании только одной границы или неверном формате — **400**. `dateFrom` не может быть позже `dateTo`.

### Успешный ответ (200)

```json
{
  "page": 1,
  "pageSize": 50,
  "totalItems": 1,
  "totalPages": 1,
  "items": [
    {
      "number": "000001234",
      "date": "2026-08-25T15:40:00",
      "seller": "Supplier Ltd",
      "sellerCode": "1201",
      "currency": "USD",
      "supplierNumber": "INV-7788",
      "supplierDate": "2026-08-25T00:00:00",
      "posted": true,
      "amount": 761,
      "items": [
        {
          "item": "iPhone 15",
          "itemCode": "10045",
          "itemSku": "",
          "qty": 2,
          "price": 350.5,
          "amount": 701
        }
      ]
    }
  ]
}
```

Структура элемента списка совпадает с полями успешного **POST** (без `success` / `error` / `replaced`): `number`, `date`, `seller`, `sellerCode`, `currency`, `supplierNumber`, `supplierDate`, `posted`, `amount`, `items[]`.

Прикреплённые файлы в ответ **не** входят: нет полей `fileName`, списка вложений и отдельного эндпоинта скачивания. Файлы видны в интерфейсе 1С на форме `_Инвойс` (вместе с файлами `ДокументОснование`, если он заполнен).

### Ошибки GET

| HTTP | Когда |
|------|--------|
| **401** | Нет / неверный `X-Api-Key` |
| **400** | Некорректные параметры; несколько документов на один номер; поставщик не найден |
| **404** | Инвойс не найден (в т.ч. вне поставщиков учётной записи) |
| **500** | Непредвиденная ошибка сервера |

```json
{
  "error": "Текст ошибки"
}
```

## POST `/invoices`

**Назначение:** создать инвойс или полностью заменить существующий (upsert) и провести документ.

**Запрос:**  
`POST /trade/hs/stock/invoices`

### Ключ upsert

Существующий документ ищется по паре:

- поставщик (`sellerCode` / `alias`);
- номер инвойса поставщика (`supplierNumber` → `НомерИнвойсаПоставщика`).

| Ситуация                                    | Поведение                                                            |
| ------------------------------------------- | -------------------------------------------------------------------- |
| Не найден                                   | Создаётся новый `Инвойс`, проводится                                 |
| Найден, **нет** приходных по `Инвойсу`      | Полная перезапись шапки и ТЧ `Товары`, проведение (`replaced: true`) |
| Найден, есть приходная (в т.ч. проведённая) | **400**, замена запрещена                                            |

### Поля заголовка

| Поле JSON | Синонимы | Обязательный | Описание |
|-----------|----------|--------------|----------|
| `sellerCode` | `supplierCode`, `code` | да\* | Код поставщика (`Контрагенты.Код`) |
| `alias` | `seller`, `supplier` | да\* | Псевдоним или наименование поставщика |
| `currency` | | да | Код валюты (`Валюты.Код` или `КодISO`) |
| `supplierNumber` | `supplierNo`, `invoiceNumber`, `invoiceNo` | да | Номер инвойса поставщика |
| `supplierDate` | `invoiceDate` | да | Дата инвойса поставщика (`yyyy-MM-dd`) |
| `date` | | нет | Дата документа; по умолчанию — текущая дата сеанса |
| `note` | `comment` | нет | Примечание (до 200 символов) |
| `items` | | да | Массив позиций |

\* Нужен хотя бы один идентификатор поставщика (`sellerCode` / `alias` и синонимы).

### Позиции `items[]`

Серии **не** поддерживаются.

| Поле | Синонимы | Обязательный | Описание |
|------|----------|--------------|----------|
| `itemCode` | `code` | да\* | Код номенклатуры |
| `itemSku` | `sku`, `SKU` | да\* | SKU |
| `itemUpc` | `upc`, `UPC` | да\* | UPC |
| `itemJan` | `jan`, `JAN`, `jan13`, `JAN13` | да\* | JAN13 |
| `item` | `name` | да\* | Наименование (точное / неточное) |
| `qty` | `quantity`, `count` | да | Количество (> 0) |
| `price` | `purchasePrice` | да\*\* | Цена в валюте инвойса |
| `amount` | `sum`, `purchaseAmount` | да\*\* | Сумма в валюте инвойса |

\* Нужен хотя бы один способ найти номенклатуру.  
\*\* Нужны `price` и/или `amount`. Если задано только одно — второе считается из `qty`.

Тип номенклатуры — только «Товар».

### Пример запроса (JSON)

```json
{
  "sellerCode": "1201",
  "currency": "USD",
  "supplierNumber": "INV-7788",
  "supplierDate": "2026-08-25",
  "note": "API invoice",
  "fileName": "invoice-7788.pdf",
  "fileContent": "<base64-содержимое файла>",
  "items": [
    {
      "itemCode": "10045",
      "qty": 2,
      "price": 350.5
    },
    {
      "itemSku": "CABLE-USBC",
      "qty": 5,
      "amount": 60
    }
  ]
}
```

Поля `fileName` / `fileContent` опциональны — см. ниже.

### Прикреплённые файлы (POST `/invoices`)

Только **POST** поддерживает передачу файла. **PUT** вложения не принимает и не меняет.

Можно прикрепить **один** файл к создаваемому или заменяемому документу `Инвойс`. Хранение: регистр `ХранилищеФайлов`, назначение «Прочее». На форме `Инвойс` в 1С отображаются файлы самого инвойса и (если заполнено) `ДокументОснование` (`ИнвойсЗакупки`); API пишет только к `Инвойс`, файлы основания **не** изменяет.

#### Поля вложения

| Поле | Описание |
|------|----------|
| `fileName` | Имя с расширением: `invoice.pdf`, `scan.xls`, `photo.jpg` и т.п. Расширение **обязательно**. |
| `fileContent` | Содержимое в **base64** (для JSON или текстовой части multipart). |

#### Правила

| Ситуация | Поведение |
|----------|-----------|
| Ни `fileName`, ни содержимого нет | Вложения **не меняются** (при upsert существующие файлы сохраняются). |
| Только `fileName` или только содержимое | **400** |
| Некорректный base64 / пустой файл / нет расширения в имени | **400** |
| Файл с тем же именем уже есть у `_Инвойс` | Старый файл **заменяется** |
| Документ сохранён, прикрепление не удалось | **400**, в теле — данные уже записанного инвойса (`number`, `items`, …) и текст ошибки |

Порядок на сервере: сначала запись и проведение `_Инвойс`, затем прикрепление файла (вне транзакции документа). При ошибке файла документ в базе **остаётся**.

#### Способ 1 — JSON (`Content-Type: application/json`)

Все поля инвойса и вложения — один JSON-объект (см. пример выше).

#### Способ 2 — `multipart/form-data`

Заголовок: `Content-Type: multipart/form-data; boundary=...`

Варианты передачи данных:

1. **Часть `json` / `payload` / `data`** — JSON-объект с полями инвойса (`sellerCode`, `items`, …), плюс отдельно файл.
2. **Текстовые части** — те же поля, что в JSON, как отдельные поля формы (кроме `items`: массив удобнее передавать в части `json`).
3. **Файл** — один из вариантов:
   - текстовые части `fileName` + `fileContent` (base64);
   - бинарная часть с именем поля `file` или `attachment` и `filename="..."` в `Content-Disposition` (имя файла берётся из заголовка части);
   - бинарная часть `file` / `attachment` **без** `filename` — тогда отдельно текстовая часть `fileName`.

Пример (схематично):

```http
POST /trade/hs/stock/invoices
Content-Type: multipart/form-data; boundary=----boundary
X-Api-Key: your-api-token-here

------boundary
Content-Disposition: form-data; name="json"

{"sellerCode":"1201","currency":"USD","supplierNumber":"INV-7788","supplierDate":"2026-08-25","items":[{"itemCode":"10045","qty":2,"price":350.5}]}
------boundary
Content-Disposition: form-data; name="file"; filename="invoice-7788.pdf"
Content-Type: application/pdf

<бинарное содержимое PDF>
------boundary--
```

#### Типичные ошибки вложения (400)

| Текст / смысл |
|---------------|
| `Укажите fileName вместе с содержимым файла.` |
| `Укажите fileContent (base64) или передайте бинарную часть файла.` |
| `Некорректный fileContent: ожидается base64.` |
| `Пустое содержимое файла.` |
| `fileName должен содержать расширение (например invoice.pdf).` |
| `Не удалось прикрепить файл к инвойсу.` |

### Успешный ответ (200)

```json
{
  "success": true,
  "error": "",
  "number": "000001234",
  "date": "2026-08-25T15:40:00",
  "seller": "Supplier Ltd",
  "sellerCode": "1201",
  "currency": "USD",
  "supplierNumber": "INV-7788",
  "supplierDate": "2026-08-25T00:00:00",
  "posted": true,
  "amount": 761,
  "replaced": false,
  "items": [
    {
      "item": "iPhone 15",
      "itemCode": "10045",
      "itemSku": "",
      "qty": 2,
      "price": 350.5,
      "amount": 701
    },
    {
      "item": "Cable USB-C",
      "itemCode": "20010",
      "itemSku": "CABLE-USBC",
      "qty": 5,
      "price": 12,
      "amount": 60
    }
  ]
}
```

| Поле | Описание |
|------|----------|
| `replaced` | `true`, если выполнен upsert существующего инвойса |
| `amount` | Сумма документа (`Сумма`, в валюте учёта закупки с учётом курса) |
| `price` в `items` | `ЦенаИнвойса` (валюта инвойса) |

Поле `note` в ответ **не** возвращается (только на вход POST). Сведений о прикреплённом файле в ответ нет.

### Ошибки

| HTTP | Когда |
|------|--------|
| **401** | Нет / неверный `X-Api-Key` |
| **400** | Ошибка валидации; поставщик/товар/валюта не найдены; есть приходная по инвойсу; сбой проведения; ошибка полей/содержимого вложения (документ при этом может быть уже записан) |
| **500** | Непредвиденная ошибка сервера |

```json
{
  "success": false,
  "error": "Текст ошибки"
}
```

При блокировке замены из‑за приходной в теле дополнительно могут быть заполнены реквизиты найденного инвойса (`number`, `date`, `items` и т.д.).

### Поведение в 1С

1. Создаётся или открывается `Инвойс`.
2. При замене: отмена проведения (если был проведён), очистка `ВКД_Товары` и `Поставки`, перезапись шапки и строк.
3. Цены запроса — в валюте инвойса (`ЦенаИнвойса`); `ЦенаЗакупки` / `СуммаЗакупки` пересчитываются по курсу на дату документа (для базовой валюты курс = 1).
4. Документ **проводится**.
5. Если переданы `fileName` и содержимое — файл прикрепляется к `Инвойс` (при совпадении имени — замена).

## PUT `/invoices`

**Назначение:** добавить позиции `items` к существующему инвойсу (аналог **PUT `/orders`**). Шапка документа не меняется; цены/`currency` из тела для шапки **не** применяются — используются валюта и курс инвойса.

**Запрос:**  
`PUT /trade/hs/stock/invoices`  
`Content-Type: application/json`

Прикреплённые файлы **не** принимаются.

Идентификация документа (тело JSON и/или query-параметры URL) — нужен хотя бы один номер:

| Поле             | Синонимы                                   | Описание                                  |
| ---------------- | ------------------------------------------ | ----------------------------------------- |
| `number`         | `documentNumber`                           | Номер документа `_Инвойс` в 1С            |
| `supplierNumber` | `supplierNo`, `invoiceNumber`, `invoiceNo` | Номер инвойса поставщика                  |
| `date`           |                                            | Дата документа (`yyyy-MM-dd`) — уточнение |
| `sellerCode`     | `supplierCode`, `code`                     | Код поставщика (уточнение)                |
| `alias`          | `seller`, `supplier`                       | Псевдоним поставщика (уточнение)          |

Документ должен быть в иерархии поставщиков учётной записи. Если по инвойсу уже есть **приходная** накладная — изменение запрещено (**400**, при проведённой приходной — **409**).

### Позиции `items[]`

Те же поля, что у **POST `/invoices`**: `itemCode` / `itemSku` / …, `qty`, `price` и/или `amount`. Серии не поддерживаются.

### Пример

Только JSON-тело:

```http
PUT /invoices
Content-Type: application/json
X-Api-Key: your-api-token-here
```

```json
{
  "number": "000001234",
  "items": [
    {
      "itemCode": "20010",
      "qty": 3,
      "price": 12
    }
  ]
}
```

Идентификация в query (тело — только `items`):

```http
PUT /invoices?supplierNumber=INV-7788&sellerCode=1201
Content-Type: application/json
X-Api-Key: your-api-token-here
```

```json
{
  "items": [
    {
      "itemSku": "CABLE-USBC",
      "qty": 2,
      "amount": 24
    }
  ]
}
```

Или по номеру поставщика в теле:

```json
{
  "supplierNumber": "INV-7788",
  "sellerCode": "1201",
  "items": [
    {
      "itemSku": "CABLE-USBC",
      "qty": 2,
      "amount": 24
    }
  ]
}
```

### Успешный ответ (200)

Те же поля, что у успешного **POST**, без `replaced`: `success`, `error`, `number`, `date`, `seller`, `sellerCode`, `currency`, `supplierNumber`, `supplierDate`, `posted`, `amount`, `items` (полный состав после добавления).

### Ошибки PUT

| HTTP | Когда |
|------|--------|
| **401** | Нет / неверный `X-Api-Key` |
| **400** | Валидация; поставщик/товар не найдены; есть непроведённая приходная; сбой проведения |
| **404** | Инвойс не найден |
| **409** | Есть **проведённая** приходная накладная |
| **500** | Непредвиденная ошибка сервера |

### Поведение в 1С

1. Поиск `Инвойс` по номеру / номеру поставщика в рамках поставщиков учётной записи.
2. Проверка отсутствия приходной по `ВКД_Инвойс`.
3. При необходимости — отмена проведения.
4. Добавление строк в `ВКД_Товары` (цены в валюте инвойса, пересчёт закупки по курсу документа).
5. Пересчёт итогов и проведение.
