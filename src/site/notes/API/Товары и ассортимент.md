# GET `/goods`

**Описание:**  
    получение списка номенклатуры типа **Товар**, которая за последние *N* месяцев имела ненулевой остаток на складах учётной записи **или** участвовала в движениях по этим складам. Метод возвращает карточные данные товара (без остатков и цен). Для остатков и цен используйте **GET /balances** и **GET /leftover**.

**Запрос**  
    GET /trade/hs/stock/goods

**Авторизация:**  
    заголовок `X-Api-Key` (токен [[Справочники (НСИ)/Учетные записи интеграции\|учётной записи интеграции]]).

---

## Параметры

| параметр | синонимы | описание | обязательный |
| --- | --- | --- | --- |
| `page` | — | номер страницы, начиная с 1 (по умолчанию `1`) | нет |
| `pageSize` | `limit` | размер страницы, 1–500 (по умолчанию `500`) | нет |
| `months` | `monthsCount` | глубина периода в месяцах, 1–120 (по умолчанию `12`) | нет |
| `warehouse` | — | наименование склада; без параметра — все склады учётной записи | нет |
| `warehouseCode` | `warehouseId`, `code` | числовой код склада (приоритетнее `warehouse`) | нет |

---

## Поведение

- авторизация — заголовок `X-Api-Key`, как у остальных методов Stock API;
- склад проверяется по списку, доступному учётной записи (для администратора API — по общим складам); при указании недоступного склада — **400** с текстом «Нет доступа к указанному складу.»;
- если у учётной записи не заданы склады — **400** («Для учётной записи не заданы склады.»);
- период: от `months` месяцев назад (начало дня) до текущей даты (конец дня);
- в выборку попадает номенклатура, у которой на отобранных складах выполняется **хотя бы одно** условие:
  - ненулевой остаток на **начало** периода;
  - **движение** в регистре `ОстаткиТовара` за период;
  - ненулевой **текущий** остаток;
- из справочника `Номенклатура` отбираются только элементы (не группы), не помеченные на удаление, с типом **Товар**;
- сортировка — по наименованию номенклатуры;
- при отборе по одному складу в ответ добавляются поля `warehouse` и `warehouseCode`.

---

```

GET /trade/hs/stock/goods?warehouse=Main
GET /trade/hs/stock/goods?warehouseCode=1&months=12
```

# GET `/goodGroups`

**Описание:**  
    папки справочника **Номенклатура**, в которые можно помещать новый товар. Возвращаются только конечные группы: без живых подчинённых папок, без пометки удаления и без признака **Выводить из ассортимента**. Товары внутри папки на отбор не влияют.

**Запрос**  
    GET /trade/hs/stock/goodGroups

**Авторизация:**  
    заголовок `X-Api-Key` (токен [[Справочники (НСИ)/Учетные записи интеграции\|учётной записи интеграции]]).

**Параметры:**  
    нет.

---

## Поведение

- список общий для всех учётных записей: склады и ассортимент учётной записи на выборку не влияют;
- папка попадает в ответ, если одновременно:
  - это группа;
  - нет пометки удаления;
  - **Выводить из ассортимента** = ложь;
  - нет подчинённых групп без пометки удаления (помеченные на удаление подпапки не считаются);
- сортировка — по наименованию;
- код группы из `code` передаётся в **POST /goods** как `parentCode`.

---

## Пример

```
GET /trade/hs/stock/goodGroups
```

---

```json
{
    "items": [
        {
            "code": "15497",
            "name": "Чехлы"

        {

        }

}
```

| поле | описание |
| --- | --- |
| `code` | код папки номенклатуры |
| `name` | наименование папки |

# POST `/goods`

**Описание:**  
    создание элемента справочника **Номенклатура**. Тип всегда **Товар**. Ассортимент в запрос не передаётся: он копируется со склада. Склад берётся только из табличной части **Склады** текущей учётной записи (общие склады администратора API здесь не используются).

**Запрос**  
    POST /trade/hs/stock/goods  
    `Content-Type: application/json`

**Авторизация:**  
    заголовок `X-Api-Key` (токен [[Справочники (НСИ)/Учетные записи интеграции\|учётной записи интеграции]]).

---

## Параметры тела

| параметр | синонимы | описание | обязательный |
| --- | --- | --- | --- |
| `code` | `itemCode` | код товара, целое положительное число до 7 знаков; должен быть свободен во всём справочнике | да |
| `name` | `item` | наименование, до 150 символов | да |
| `parentCode` | `groupCode` | код папки-родителя; см. GET `/goodGroups` | одно из двух с `parent` |
| `parent` | `group`, `parentName` | наименование папки-родителя | одно из двух с `parentCode` |
| `warehouseCode` | `warehouseId` | числовой код склада | одно из двух с `warehouse` |
| `warehouse` | — | наименование склада | одно из двух с `warehouseCode` |
| `sku` | `itemSku` | SKU, до 12 символов | нет |
| `upc` | `itemUpc` | UPC, до 12 символов | нет |
| `jan13` | `itemJan` | JAN-13, до 13 символов | нет |
| `serialAccounting` | — | учёт по сериям; если не передан — `false`. Допустимы `true` / `false`, `1` / `0`, `yes` / `no` | нет |
| `employeeCode` | `employeePin` | оператор склада; обязателен, только если для метода `goodsPOST` в учётной записи включена идентификация сотрудника | условно |

Если переданы и код, и наименование родителя, оба должны указывать на одну и ту же папку. То же для склада: код и наименование проверяются вместе.

Папка-родитель — любая группа без пометки удаления. Конечность папки (как в GET `/goodGroups`) при создании не проверяется.

При записи заполняются:

- `ТипНоменклатуры` = **Товар**;
- `Ассортимент` = ассортимент склада;
- `УчетПоСериям` — из `serialAccounting`;
- код, наименование, родитель, SKU, UPC, JAN-13.

Производитель, поставщик, вес и описание этим методом не задаются.

Если у склада не заполнен ассортимент, товар не создаётся. Текст ошибки: `У склада ХХХ не установлен ассортимент в 1С`.

---

## Пример

```http
POST /trade/hs/stock/goods
Content-Type: application/json
X-Api-Key: <токен>

{
    "code": "10025",
    "name": "Чехол Ozon, артикул OZ-15",
    "parentCode": "15497",
    "warehouseCode": "7",
    "sku": "OZ-15",
    "upc": "0194253401999",
    "serialAccounting": false
}
```

---

## Ответ (200)

```json
{
    "success": true,
    "error": "",
    "item": "Чехол Ozon, артикул OZ-15",
    "itemCode": "10025"
}
```

| поле | описание |
| --- | --- |
| `success` | `true`, если элемент записан |
| `error` | пустая строка при успехе |
| `item` | наименование созданного товара |
| `itemCode` | код созданного товара |

При ошибке проверки те же поля: `success` = `false`, текст в `error`, `item` и `itemCode` пустые. Код ответа **400**.

---

## Ошибки

| код | когда |
| --- | --- |
| `401` | неверный или отсутствующий API-ключ (`success: false`) |
| `400` | тело не JSON, не передан обязательный сотрудник, код или наименование пустые или неверного формата, код уже занят, папка не найдена или их несколько, склад недоступен или их несколько, у склада нет ассортимента, SKU / UPC / JAN-13 длиннее реквизита, `serialAccounting` не булево |
| `500` | внутренняя ошибка при записи или разборе запроса |

Типовые тексты `error` при **400**:

| ситуация | `error` |
| --- | --- |
| не указан код | `Укажите код номенклатуры (code).` |
| код не число | `Код номенклатуры не числовой: '...'` |
| код не целое положительное | `Код номенклатуры должен быть целым положительным числом: '...'` |
| код длиннее 7 знаков | `Код номенклатуры длиннее 7 знаков.` |
| код занят | `Номенклатура с кодом N уже существует.` |
| не указано наименование | `Укажите наименование номенклатуры (name).` |
| наименование длиннее 150 символов | `Наименование номенклатуры длиннее 150 символов.` |
| не указан родитель | `Укажите код или наименование родителя (parentCode или parent).` |
| папка не найдена | `Группа номенклатуры (родитель) не найдена.` |
| несколько папок с одним именем | `Найдено несколько групп номенклатуры с наименованием '...'. Укажите parentCode.` |
| не указан склад | `Укажите код или наименование склада (warehouseCode или warehouse).` |
| код склада не число | `Код склада не числовой: '...'` |
| склад не в ТЧ учётной записи | `Не найден склад (или нет доступа к указанному складу) с кодом '...'` либо то же с наименованием |
| несколько складов с одним именем | `Найдено несколько складов с наименованием '...'. Укажите warehouseCode.` |
| у склада нет ассортимента | `У склада ХХХ не установлен ассортимент в 1С` |
| длинные коды товара | `SKU длиннее 12 символов.` / `UPC длиннее 12 символов.` / `JAN13 длиннее 13 символов.` |
| неверный признак серий | `Параметр serialAccounting должен быть булевым.` |

Нечисловой `parentCode` возвращает те же тексты, что и нечисловой код товара (`Код номенклатуры не числовой` и соседние).
