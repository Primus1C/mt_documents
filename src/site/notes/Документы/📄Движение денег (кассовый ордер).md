Единый документ кассы/банка: приход и расход денег с разным смыслом операции. Вид операции (**Вид движения денег**) полностью меняет поля формы, проверки и учёт.

### Где открыть
**Деньги → Движения денег**

Список отбирается по **доступным кассам** пользователя. Без текущей кассы документ не открыть (ошибка «Не задана текущая касса!»).

---

### Общие поля

| Поле                              | Назначение                                        |
| --------------------------------- | ------------------------------------------------- |
| **Вид**                           | Тип операции (главный переключатель)              |
| **Тип (Приход/Расход)**           | Только просмотр — ставится сам по виду            |
| [[Справочники (НСИ)/Денежные счета\|Денежный счёт]] | Касса/счёт операции                               |
| **Сумма, Валюта**                 | Сумма и валюта документа                          |
| [[Документы/Окончательно\|Окончательно]]                  | Документ «закрыт», полный учёт выполнен           |
| **Корреспонденция**               | Краткая подпись (покупатель, статья, «в: касса»…) |
| **Примечание**                    | Свободный текст                                   |

### Табличные части

| ТЧ                    | Когда                                                                        |
| --------------------- | ---------------------------------------------------------------------------- |
| **Зачеты (Привязки)** | Оплата покупателя / поставщику — закрытие долгов документами                 |
| **Инвойсы**           | Оплата поставщику (если у контрагента «Привязывать инвойсы») и **Логистика** |

---

### Жизненный цикл

```text
Черновик (Окончательно = Нет)
    → заполнение, запись
    → в учёте как «незакрытый» (почти все виды)
    → Установить → Окончательно = Да → полные движения по кассе и связанным регистрам
    → привязки зачётов / инвойсов (после закрытия)
    → Снять → снова черновик (если нет блокирующих привязок)
```

| Действие | Смысл |
|---|---|
| **Установить** | Проверки по виду → подтверждение → закрытие и проведение |
| **Снять** | Снять «Окончательно», если нет блокирующей оплаты/привязки |
| Привязать зачёты | Только после **Окончательно** и проведения |

Пока документ не окончательный — правятся сумма, валюта, вид, контрагент. После закрытия шапка блокируется.  
Отменить проведение при **Окончательно** нельзя. 
Копия сбрасывает закрытие, привязки и инвойсы. Есть команда **«Копировать с минусом»** (сторно-подобная копия).

## Виды операций

### 1. Оплата покупателя
**Зачем:** принять оплату от покупателя.  
**Тип:** Приход.

| Поля | Контрагент (покупатель), сумма, валюта, касса; итоги/остатки; **Зачеты** |
|---|---|
| Обязательно | Покупатель, сумма ≠ 0 |
| Учёт | Деньги на кассу; привязки закрывают долг / создают предоплату; возможна курсовая разница |

После закрытия — **Привязать** (обработка привязки долгов к накладным/заказам). Непривязанный остаток — предоплата покупателя.

---

### 2. Оплата поставщику
**Зачем:** оплатить поставщику.  
**Тип:** Расход.

| Поля | Контрагент (поставщик), сумма, валюта, касса; **Зачеты**; при флаге контрагента — **Инвойсы**, курс оплаты, КР |
|---|---|
| Обязательно | Поставщик, сумма ≠ 0 |
| Учёт | Деньги с кассы; долг/предоплата поставщику; при инвойсах — расчёты по инвойсам и статусы оплаты |

**Два режима** (реквизит контрагента **Привязывать инвойсы**):

| Режим | UI | Смысл |
|---|---|---|
| Классический | Зачеты на накладные | Долг поставщику |
| По инвойсам | ТЧ Инвойсы (+ зачеты) | Оплата закупочных `_Инвойс`, подбор неоплаченных |

При партионной валюте на кассе расход контролирует остаток партий.

Оплата поставщику возможна только (согласовано 21.05.2026):
- в валюте инвойса (закупки)
- в долларе
В документах с установленным "Окончательно" можно работать с привязками (приходных накладных и инвойсов).
При установке пользователем значения валюты, система ищет, есть ли у этого поставщика инвойсы в выбранной валюте и в зависимости от результата реализует один из сценариев:
#### Оплата поставщику в валюте инвойса
Значения реквизитов ТЧ Инвойсы:
- Сумма - в валюте текущего документа
- СуммаВБазВалюте - в долларах
- СуммаВВалютеИнвойса - не заполняется
#### Оплата поставщику в валюте, отличной от валюты инвойса
Значения реквизитов ТЧ Инвойсы:
- Сумма - в валюте текущего документа
- СуммаВБазВалюте - не заполняется
- СуммаВВалютеИнвойса - в валюте инвойса
#### Оплата поставщику с привязкой инвойсов
При оплате с привязкой инвойсов (у [[Справочники (НСИ)/Контрагенты\|контрагента]] установлена пометка "Привязывать инвойсы") становится доступным **сумма курсовой разницы**. Эту сумма зачтется во взаиморасчетах по единственному инвойсу таб.части "Привязка инвойсов" (если инвойсов несколько, проведение вызовет ошибку). Также сумма курсовой разницы отразится в доходах/расходах.

---

### 3. Расходы
**Зачем:** хозяйственный/прочий расход по статье.  
**Тип:** Расход.

| Поля | Статья расходов, опционально контрагент, сумма, валюта, касса |
|---|---|
| Обязательно | Статья с видом **Расход** |
| Учёт | Расход с кассы + запись в доходы/расходы по статье |

На долги контрагента не влияет.

---

### 4. Доходы
**Зачем:** прочий приход по статье (не оплата покупателя).  
**Тип:** Приход.

| Поля | Статья доходов, опционально контрагент, сумма, валюта, касса |
|---|---|
| Обязательно | Статья с видом **Доход** |
| Учёт | Приход на кассу + доходы/расходы по статье |

---

### 5. Перемещение
**Зачем:** переложить деньги между кассами **в той же валюте**.  
**Тип:** Расход (с кассы «откуда»).

| Поля | Касса откуда, касса **куда**, сумма, валюта. Контрагента нет |
|---|---|
| Обязательно | Касса куда |
| Учёт | Расход с одной кассы + приход на другую; при партионном учёте — перенос партий |

Нельзя переносить партионную валюту с кассы **без** парт.учёта на кассу **с** парт.учётом.

---

### 6. Обмен валюты
**Зачем:** купить/продать валюту.  
**Тип:** Расход (отдаваемая валюта). Контрагент очищается.

| Поля | Сумма/валюта «отдаём»; касса и валюта «получаем»; курс; сумма обмена; курсовая разница; «Рассчитывать средний курс» |
|---|---|
| Обязательно | Касса куда, валюта куда, сумма обмена ≠ 0 |
| Учёт | Расход одной валюты + приход другой; КР в доходы/расходы; при партионной покупке — партии валюты; опционально средний курс в справочнике курсов |

---

### 7. Подотчет
**Зачем:** выдать деньги подотчётному.  
**Тип:** Расход.

| Поля | Сотрудник, сумма, валюта, касса |
|---|---|
| Обязательно | Сотрудник |
| Учёт | Расход с кассы + остаток по подотчёту |

---

### 8. Зарплата
**Зачем:** выплата зарплаты за месяц.  
**Тип:** Расход.

| Поля | Сотрудник, **месяц з/п**, сумма, валюта, касса |
|---|---|
| Обязательно | Сотрудник и месяц |
| Учёт | Расход с кассы + выплата по зарплате (месяц к началу месяца) |

---

### 9. Ввод остатков
**Зачем:** начальный остаток на кассе (в т.ч. партий валюты).  
**Тип:** Приход.

| Особенности | Сумма **может быть 0**; не попадает в «незакрытые»; при парт.валюте — ввод партий (курс) |
|---|---|
| Учёт | Приход на кассу (если сумма ≠ 0) + партии при необходимости |
В случае партионного учета валют, который начинает вестись не с начала движений по кассе, возникает необходимость установить курс остатка денег в кассе. Это можно сделать, не устанавливая значение суммы в документе. Тогда в партионный учет валют попадет остаток на дату документа, и он будет оценен по указанному курсу. 

> [!tip] 
> Дата документа ввода остатков в этом случае должна быть началом дня, указанного в карточке *ДенежногоСчета* в реквизите *"Вести партионный учет с даты"* 

---

### 10. Инвестиции
**Зачем:** поступление (+) или возврат (−) денег инвестора.  
**Тип на форме:** Приход; направление задаёт **знак суммы**.

| Поля | Контрагент, **% инвестиций** (справочно), сумма ±, валюта, касса |
|---|---|
| Учёт | `Сумма > 0` — приход на кассу и в инвестиции; `Сумма < 0` — расход. Незакрытые не ведутся |

Процент в проведении документа не используется (для отчётов/ставок).

---

### 11. Биржа
**Зачем:** биржевая операция по статье.  
**Тип на форме:** Приход; направление — **знак суммы**.

| Поля | Статья, сумма ±, валюта, касса. Контрагент скрыт |
|---|---|
| Учёт | Аналогично инвестициям, но по регистру биржи (статья). Незакрытые не ведутся |

---

### 12. Логистика
**Зачем:** оплата логистики с разнесением на **закупочные** инвойсы (`Инвойс`) → в затраты на товары (по весу при перепроведении инвойса).  
**Тип:** Расход. Это **не** оплата поставщику.

| Поля | Затрата (номенклатура), статья, сумма, валюта, касса; ТЧ **Инвойсы**. Контрагент и зачеты накладных скрыты |
|---|---|
| Распределение | Сумма документа **поровну** между строками инвойсов (хвост — на последнюю) |
| Учёт в ДД | Только **расход с кассы**. В доходы/расходы и расчёты по инвойсам как оплата **не** пишется |
| Дальше | Связанные инвойсы перепроводятся → регистр **Затраты** по весу товара → себестоимость партий |

На форме инвойса дерево затрат показывает связанные ДД логистики.  
Отдельных жёстких проверок «затрата/статья/инвойсы обязательны» при **Установить** нет — заполнение на ответственности пользователя.  
Смена суммы шапки **не** пересчитывает доли в ТЧ автоматически (пересчёт — при изменении строк инвойсов).


Распределение идёт на **закупочные инвойсы `Инвойс`**, не на `ИнвойсПродажи`. 

#### Как работает (для пользователя)

1. Создаёте **Движение денег**, вид **Логистика** (это расход с кассы).
2. Указываете сумму, валюту, счёт, **затрату** (номенклатура) и при необходимости **статью**.
3. В ТЧ **Инвойсы** выбираете один или несколько **закупочных** инвойсов (`Инвойс`).
4. Сумма документа **делится поровну** между строками инвойсов (копейки — на последнюю).
5. После проведения / «Окончательно»:
   - списываются деньги с кассы;
   - связанные инвойсы ставятся в очередь на перепроведение;
   - при перепроведении инвойса логистика **раскладывается на товары по весу** в регистр **Затраты**.
6. Дальше эти затраты участвуют в **себестоимости партий** (в т.ч. при продаже/комиссии), а не как отдельная оплата поставщику.

#### Алгоритм (технически)

Механизм задуман как: **касса → доли на закупочные инвойсы → по весу в `Затраты` → в себестоимость партий**.  
На `ИнвойсПродажи` напрямую ничего не распределяется.

```text
ДвижениеДенег (Логистика)
  ├─ форма: Сумма / N → ТЧ Инвойсы.Сумма (поровну)
  ├─ проведение: расход РН «Деньги»
  └─ запись → РС «ДокументыКПроведению» (_Инвойс)
                    ↓
              перепроведение _Инвойс
                    ↓
         доля инвойса × (ВесСтроки / ОбщийВес)
                    ↓
              РС «Затраты» (сумма на единицу)
                    ↓
         ЗатратыПартий → цена с затратами в расходных док.
```

| Этап | База | Формула |
|---|---|---|
| Между инвойсами | число строк | `Сумма_i = Сумма / N`, остаток → последняя |
| Внутри инвойса | вес товара | `на ед. = (ВесСтроки / ОбщийВес / Кол) × Сумма_инвойса` = `(Вес_ед / ОбщийВес) × S` |
| Валюта | как в ДД | пересчёт в базовую через `РаботаСВалютой.Пересчитать2025` |

Источники суммы на инвойсе:
- все проведённые ДД с видом **Логистика** по этому инвойсу;
- если таких ДД нет — fallback на реквизит инвойса **СуммаЗатрат** (служебная номенклатура «Затраты инвойсов»).

---

#### Возможные упущения в учете

1. **Равномерный сплит между инвойсами** — слабо для логистики (обычно ждут вес, объём, сумму закупки или ручные доли; ручные доли перетираются при любом изменении ТЧ).

2. **Нет доразнесения остатков по товарам** — порог `0.000005`, хвосты отбрасываются без компенсации.

3. **Логистика не в P&L (`РасходыДоходы`)** — только удорожание запасов. Если нужна «статья расходов периода» отдельно от себестоимости — сейчас этого нет.

4. **Смешение с оплатой поставщику** — одна ТЧ `Инвойсы` на логистику и на оплату; общая логика статусов/очереди без чёткого разделения ролей.

## Сводка: что происходит при «Окончательно»

| Вид               | Касса | Долги               | Инвойсы (расчёты)          | Доходы/расходы | Прочее              |
| ----------------- | ----- | ------------------- | -------------------------- | -------------- | ------------------- |
| Оплата покупателя | +     | долг/п/о покупателя | —                          | КР             | Зачеты              |
| Оплата поставщику | −     | долг/п/о поставщику | если «Привязывать инвойсы» | КР             | Зачеты / Инвойсы    |
| Расходы           | −     | —                   | —                          | по статье      |                     |
| Доходы            | +     | —                   | —                          | по статье      |                     |
| Перемещение       | −/+   | —                   | —                          | —              | две кассы           |
| Обмен валюты      | −/+   | —                   | —                          | КР             | курс, партии        |
| Подотчет          | −     | —                   | —                          | —              | подотчёт            |
| Зарплата          | −     | —                   | —                          | —              | зарплата            |
| Ввод остатков     | +     | —                   | —                          | —              | партии              |
| Инвестиции        | ±     | —                   | —                          | —              | инвестиции          |
| Биржа             | ±     | —                   | —                          | —              | биржа               |
| Логистика         | −     | —                   | не как оплата              | —              | затраты на `Инвойс` |

Любая ненулевая **сумма КР** уходит в статьи курсовой разницы.

При **Окончательно = Нет** почти все виды пишут только «незакрытый документ» (исключения: инвестиции, биржа, ввод остатков).

## Шпаргалка «какой вид выбрать»

| Ситуация | Вид |
|---|---|
| Клиент заплатил | Оплата покупателя |
| Платим поставщику | Оплата поставщику |
| Аренда, услуги, прочий расход / доход | Расходы / Доходы |
| Между своими кассами | Перемещение |
| Купили/продали валюту | Обмен валюты |
| Выдали под отчёт | Подотчет |
| Выплатили зарплату | Зарплата |
| Стартовые остатки кассы | Ввод остатков |
| Деньги инвестора (±) | Инвестиции |
| Биржевая операция | Биржа |
| Оплатили логистику и разнесли на инвойсы закупки | Логистика |

---

## На что обратить внимание

1. **Вид** выбирайте до заполнения привязок — от него зависит весь документ.  
2. Полный учёт денег — только после **Установить**.  
3. Оплата поставщику ≠ логистика: первая гасит долг/инвойс, вторая удорожает товар.  
4. Привязки зачётов — после закрытия; инвойсы у поставщика — если включено у контрагента.  
5. Партионная валюта: расход и перемещение жёстче контролируются.  
6. Список документов — только по доступным кассам пользователя.
